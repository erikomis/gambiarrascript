GambiarraScript tem concorrencia de verdade: `bora` dispara uma gambiarra numa
goroutine, `espera` aguarda o resultado, `cano` cria um canal pra sincronizar
produtores e consumidores, e `paralelo` mapeia uma lista em paralelo. Funciona
igual na VM e no tree-walker.

<Callout title="Por baixo dos panos">
  Tudo vira goroutine/channel do Go. Cada chamada ganha seu proprio escopo; o
  `mostra` concorrente usa um lock interno pra nao intercalar meia linha com
  meia linha.
</Callout>

## bora: dispara em paralelo

`bora fn(args)` e uma **expressao prefixo**: roda `fn(args)` numa goroutine e
devolve na hora um **futuro**, sem bloquear.

```gambiarrascript
gambiarra demora(n)
    bota out = 0
    pra_cada i de 1 ate n
        out += i
    acabou_finalmente
    funciona out
acabou_finalmente

bota f1 = bora demora(100)
bota f2 = bora demora(1000)

mostra "as duas ja tao rodando em paralelo..."
mostra espera(f1)   # 5050
mostra espera(f2)   # 500500
```

Formas de uso:

```gambiarrascript
gambiarra avisa(msg)
    mostra msg
acabou_finalmente

bora avisa("salve")              # fire-and-forget (ninguem espera)
bota f = bora avisa("oi")        # guarda o futuro pra esperar depois
espera(f)
```

Cuidado com o fire-and-forget: quando o script principal termina, o processo acaba —
goroutine solta que ainda nao rodou **morre junto** (no exemplo acima o
`"salve"` pode nem aparecer). Se o resultado importa, guarde o futuro e
`espera`.

Regras do `bora`:

- So aceita **uma chamada** a direita: `bora fn(args)`. Nao rola `bora x`,
  `bora 1 + 1` nem `bora gambiarra() ... acabou_finalmente` direto — guarde a
  lambda numa variavel e chame: `bota tarefa = gambiarra() ... acabou_finalmente`
  e depois `bora tarefa()`.
- Os **argumentos** sao avaliados antes, na goroutine de quem chamou; so a
  chamada em si vai pro paralelo. Entao `bora f(espera(outro))` espera o
  `outro` antes de disparar.
- Vale pra builtin tambem: `bora espera_ms(100)`.

## espera: aguarda o futuro

`espera(futuro)` bloqueia ate o futuro resolver e devolve o valor. Tambem
aceita **uma lista de futuros** e devolve a lista de valores, na ordem
original:

```gambiarrascript
gambiarra demora(n)
    bota out = 0
    pra_cada i de 1 ate n
        out += i
    acabou_finalmente
    funciona out
acabou_finalmente

bota fs = [bora demora(100), bora demora(1000), bora demora(10000)]
mostra espera(fs)           # [5050, 500500, 50005000]
```

`espera` e builtin, nao palavra-chave: `bora` + `espera` sao o async/await da
linguagem.

### Desambiguacao com assert de teste

`espera` tem **dois papeis**, separados pelo numero de argumentos:

| Aridade | O que faz |
| --- | --- |
| 1 arg (futuro ou lista de futuros) | aguarda — **wait de concorrencia** |
| 2 args (recebido, esperado) | assert de teste (veja [gs testa](/docs/cli#gs-testa)) |

## cano: canal de mensagens

`cano([capacidade])` cria um canal (Go channel). Sem argumento = **sincrono**
(`envia` bloqueia ate alguem receber). Com capacidade = **bufferizado**
(`envia` so bloqueia quando o buffer enche).

| Builtin | Devolve |
| --- | --- |
| `cano([cap])` | um cano novo |
| `envia(cano, valor)` | `nada` (bloqueia ate ter espaco/receptor; cano fechado da erro) |
| `recebe(cano)` | o valor (ou `nada` se o cano fechou e esvaziou) |
| `fecha(cano)` | `nada` (pode chamar de novo sem dar erro) |

Os mesmos tres servem pra **conexao de rede** (`conecta_tcp`, `escuta_tcp`,
`conecta_udp`): o laco `enquanto` que consome um cano consome um socket. Veja
[Rede (TCP/UDP)](/docs/rede).

### Produtor / consumidor

```gambiarrascript
gambiarra produtor(c)
    pra_cada i de 1 ate 3
        envia(c, i)
    acabou_finalmente
    fecha(c)
acabou_finalmente

bota c = cano(2)        # buffer de 2
bora produtor(c)

# consumidor na goroutine principal
enquanto deu_bom
    bota v = recebe(c)
    se_colar v == nada
        vaza
    acabou_finalmente
    mostra "consumi " + v
acabou_finalmente
# consumi 1 / consumi 2 / consumi 3
```

### Cano sincrono (handshake)

```gambiarrascript
bota pronto = cano()      # sincrono

bota prepara = gambiarra(c)
    # ... prepara algo ...
    envia(c, "pronto")    # so avanca quando a main estiver no recebe
acabou_finalmente

bora prepara(pronto)
mostra recebe(pronto)     # pronto
```

### Fan-out / fan-in

```gambiarrascript
gambiarra trabalhador(id, saida)
    pra_cada i de 1 ate 2
        envia(saida, "${id}:${i}")
    acabou_finalmente
acabou_finalmente

bota saida = cano(10)
bora trabalhador("A", saida)
bora trabalhador("B", saida)

bota recebidos = []
pra_cada i de 1 ate 4
    adiciona(recebidos, recebe(saida))
acabou_finalmente
ordena(recebidos)          # a ordem de chegada varia; ordena pra conferir
mostra recebidos           # [A:1, A:2, B:1, B:2]
```

## paralelo: mapeia em paralelo

`paralelo(lista, fn)` chama `fn(item)` pra cada item, cada um na sua
goroutine (no maximo 256 de uma vez), e devolve os resultados **na ordem
original**. Se alguma chamada der erro, o `paralelo` estoura com o primeiro.

```gambiarrascript
mostra paralelo([1, 2, 3], gambiarra(x) funciona x * 10 acabou_finalmente)   # [10, 20, 30]
```

## Estado compartilhado

Cada chamada (com `bora` ou nao) tem seu proprio escopo, e **atribuir** dentro
da gambiarra cria variavel local (veja [Funcoes](/docs/funcoes#closures)).
Entao uma goroutine nao consegue mudar uma variavel de fora:

```gambiarrascript
bota contador = 0
gambiarra tenta()
    contador += 1          # cria um "contador" local (o gs check avisa)
    funciona contador
acabou_finalmente

mostra espera(bora tenta())   # 1
mostra contador               # 0 — o de fora nao mudou
```

**Listas**, **dicionarios** e **conjuntos** sao passados por referencia, entao
mutar o conteudo deles e visivel por todo mundo. E pode mutar de varias
goroutines ao mesmo tempo (`bora`, `paralelo`, handlers do servidor): igual o
GIL do Python, **cada operacao e atomica** — ler, escrever, `adiciona`,
`remove`, `tamanho`, `pra_cada` — e nunca derruba o processo nem perde
escrita. `pra_cada` numa colecao que outra goroutine esta mexendo percorre um
retrato tirado no comeco do laco.

```gambiarrascript
bota visitas = []
gambiarra visita(id)
    pra_cada i de 1 ate 1000
        adiciona(visitas, id)
    acabou_finalmente
acabou_finalmente

espera([bora visita("a"), bora visita("b"), bora visita("c")])
mostra tamanho(visitas)    # 3000, sempre
```

O que **nao** e atomico e a operacao **composta**: `bota d["n"] = d["n"] + 1`
sao duas operacoes (le, depois escreve), e duas goroutines podem ler o mesmo
valor e uma escrita sumir. Pra isso tem `trava`.

## trava e com_trava

`trava()` cria um lock; `com_trava(t, gambiarra)` roda a gambiarra (sem
argumentos) segurando a trava e devolve o que ela devolver:

```gambiarrascript
bota t = trava()
bota placar = {"n": 0}

gambiarra soma_muito()
    pra_cada i de 1 ate 1000
        com_trava(t, gambiarra()
            bota placar["n"] = placar["n"] + 1
        acabou_finalmente)
    acabou_finalmente
acabou_finalmente

bota fs = []
pra_cada i de 1 ate 10
    adiciona(fs, bora soma_muito())
acabou_finalmente
espera(fs)
mostra placar["n"]         # 10000, sempre
```

- A trava e solta **sempre**: se a gambiarra der erro, o erro sobe normal pra
  quem chamou o `com_trava` (da pra pegar com `arruma`) e a trava ja esta
  livre.
- **Nao e reentrante**: chamar `com_trava` na mesma trava de dentro da propria
  gambiarra da erro (`essa trava ja ta com voce`) em vez de travar pra sempre.
  Outra goroutine pedindo a mesma trava so espera a vez.
- Segure a trava o minimo possivel: nada de `busca`, `espera_ms` ou `envia`
  pra rede la dentro — todo mundo que quer a trava fica parado esperando.
- `tipo(trava())` e `"trava"`.

Outras saidas, quando cabem:

1. Cada goroutine calcula o seu e devolve com `funciona`; junte tudo com
   `espera(lista_de_futuros)` ou use `paralelo`.
2. Ou use um `cano`: os trabalhadores mandam resultados pelo cano e uma so
   goroutine consome e acumula.

## Limite

Nao ha limite no `bora` (cuidado com fan-out gigante). O `paralelo` limita a
256 goroutines simultaneas. Se precisar de fan-out massivo, prefira `paralelo`
ou monte um pool com `cano`.

## Erros em goroutines

Erro de runtime dentro da `bora fn` fica guardado no futuro e estoura no
`espera(f)`. Da pra pegar com `arruma`:

```gambiarrascript
gambiarra divide(a, b)
    funciona a / b
acabou_finalmente

arruma
    mostra espera(bora divide(10, 0))
quebrou erro
    mostra "deu ruim: " + erro_msg(erro)
acabou_finalmente
```

## Receitas rapidas

### N goroutines, espera todas

```gambiarrascript
gambiarra tarefa(id)
    funciona "resultado-" + id
acabou_finalmente

bota fs = []
pra_cada i de 1 ate 5
    adiciona(fs, bora tarefa(i))
acabou_finalmente
mostra espera(fs)  # [resultado-1, resultado-2, resultado-3, resultado-4, resultado-5]
```

### Corrida: o primeiro que volta ganha

```gambiarrascript
gambiarra lento(ms, nome)
    espera_ms(ms)
    funciona nome
acabou_finalmente

gambiarra corre(ms, nome, chegada)
    envia(chegada, lento(ms, nome))
acabou_finalmente

bota chegada = cano(2)
bora corre(200, "devagar", chegada)
bora corre(20, "ligeiro", chegada)
mostra recebe(chegada)     # ligeiro
```

Troque `lento` por um `busca(url)` e voce tem "a API que responder primeiro".

### Pipeline

```gambiarrascript
gambiarra gerador(saida)
    pra_cada i de 1 ate 5
        envia(saida, i)
    acabou_finalmente
    fecha(saida)
acabou_finalmente

gambiarra quadrado(entrada, saida)
    enquanto deu_bom
        bota v = recebe(entrada)
        se_colar v == nada
            vaza
        acabou_finalmente
        envia(saida, v * v)
    acabou_finalmente
    fecha(saida)
acabou_finalmente

bota c1 = cano(5)
bota c2 = cano(5)
bora gerador(c1)
bora quadrado(c1, c2)

enquanto deu_bom
    bota v = recebe(c2)
    se_colar v == nada
        vaza
    acabou_finalmente
    mostra v
acabou_finalmente
# 1, 4, 9, 16, 25
```

## O que **nao** existe ainda

- `select` pra esperar em varios canos ao mesmo tempo.
- Atomicos / compare-and-swap.
- Cancelar um futuro que ja foi disparado.

Se quiser `select` de multiplos `cano`, vale o PR.
