description: Orientacao a objeto no modelo do Go — treta (struct), metodo com receiver, combinado (interface implicita), puxadinho (embedding) e cardapio (enum). Sem class, this, new nem heranca.
---

GambiarraScript copia o jeito do Go de fazer POO: **composicao no lugar de
heranca**, interface satisfeita **pelo comportamento** (sem declarar nada) e
"construtor" so por convencao. Nao existe `class`, `extends`, `this` nem
`new`.

| Conceito | GambiarraScript | Go |
| -------- | --------------- | -- |
| struct | `treta Ponto` ... `acabou_finalmente` | `type Ponto struct` |
| instancia | `Ponto{x: 1, y: 2}` / `Ponto{1, 2}` | `Ponto{X: 1, Y: 2}` |
| metodo | `gambiarra (p Ponto) distancia()` | `func (p *Ponto) Distancia()` |
| interface | `combinado Forma` ... `acabou_finalmente` | `type Forma interface` |
| embedding | um campo que e so o nome da treta (`Animal`) | idem |
| construtor | `gambiarra nova_ponto(x, y)` | `func NewPonto(x, y)` |
| type switch | `escolhe tipo(v)` / `caso "Ponto"` (ou o padrao `caso Ponto{x, y}`) | `switch v.(type)` |
| enum | `cardapio Cor` ... `acabou_finalmente`, `Cor.vermelho` | `const ( Vermelho Cor = iota ... )` |
| type assertion | `como_tipo(v, Ponto)` | `v.(Ponto)` |

## treta: os campos

Um campo por linha, com valor padrao opcional. O nome da treta comeca com
**maiuscula** — e assim que o parser sabe que `Ponto{...}` e uma treta e nao um
dicionario.

```gambiarrascript
treta Ponto
    x
    y = 0
acabou_finalmente

bota a = Ponto{x: 3, y: 4}   # por nome
bota b = Ponto{3, 4}         # na ordem dos campos (tem que passar todos)
bota c = Ponto{x: 7}         # faltou y: vale o padrao (0)
bota d = Ponto{}             # tudo no zero-value
mostra c                     # Ponto{x: 7, y: 0}
mostra d                     # Ponto{x: nada, y: 0}
mostra a.x + b.y             # 7
```

- **Zero-value**: o campo que o literal nao passou fica com o padrao declarado
  ou, sem padrao, com `nada` (os campos nao tem tipo, entao nao da pra ter o
  `0`/`""` do Go).
- O padrao roda **a cada instancia**: `itens = []` da uma lista nova pra cada
  uma (nao e o padrao mutavel compartilhado do Python).
- Campo que nao existe e erro, tanto no literal quanto no `bota p.z = 1`:
  campo novo so declarando na treta.
- O `{` cola no nome, na mesma linha (`Ponto{`). Uma treta de outro modulo
  funciona igual: `geo.Ponto{1, 2}`.

## Metodo: gambiarra com receiver

O receiver vem entre parenteses antes do nome. Dentro, `p.x` le e
`bota p.x = ...` (ou `p.x += ...`) escreve.

```gambiarrascript
treta Conta
    dono
    saldo = 0
acabou_finalmente

gambiarra (c Conta) deposita(valor)
    c.saldo += valor
    funciona c
acabou_finalmente

gambiarra (c Conta) extrato()
    funciona c.dono + ": " + texto(c.saldo)
acabou_finalmente

bota conta = Conta{dono: "ana"}
conta.deposita(50).deposita(25)
mostra conta.extrato()          # ana: 75
```

**Tudo por referencia**: a instancia e um objeto compartilhado (igual lista e
dicionario), entao o metodo **muda** a treta — nao tem a diferenca de receiver
por valor e por ponteiro do Go. Quer uma copia? Monte outra: `Conta{conta.dono, conta.saldo}`.

- Metodo e campo com o mesmo nome na mesma treta e erro (igual Go).
- `obj.metodo` sem chamar devolve o metodo com o receiver grudado — da pra
  guardar numa variavel ou passar pra `mapeia`, `rota`, `bora`...
- `treta`, `combinado` e metodo so podem ser declarados no **topo** do arquivo.
  Declare a treta **antes** dos metodos dela.

## "Construtor" e convencao

Nao tem `new` nem metodo magico: escreva uma gambiarra `nova_x` que devolve a
treta pronta (igual o `NewX()` do Go).

```gambiarrascript
treta Pilha
    itens = []
acabou_finalmente

gambiarra nova_pilha(...iniciais)
    bota p = Pilha{}
    pra_cada x em iniciais
        adiciona(p.itens, x)
    acabou_finalmente
    funciona p
acabou_finalmente

mostra nova_pilha(1, 2, 3)      # Pilha{itens: [1, 2, 3]}
```

## combinado: interface implicita

O combinado lista assinaturas. Qualquer treta que tenha esses metodos (com o
numero certo de parametros) **satisfaz** o combinado, sem declarar nada.

```gambiarrascript
combinado Forma
    area()
    nome()
acabou_finalmente

treta Quadrado
    lado
acabou_finalmente
gambiarra (q Quadrado) area()
    funciona q.lado * q.lado
acabou_finalmente
gambiarra (q Quadrado) nome()
    funciona "quadrado"
acabou_finalmente

mostra satisfaz(Quadrado{2}, Forma)    # deu_bom
mostra satisfaz(42, Forma)             # deu_ruim
mostra como_tipo(Quadrado{2}, Forma).area()   # 4
```

- `satisfaz(valor, Tipo)` devolve booleano. Com um combinado, confere os
  metodos; com uma treta, diz se o valor e instancia dela.
- `como_tipo(valor, Tipo)` e o type assertion: devolve o proprio valor ou
  quebra explicando o motivo ("falta o metodo area").
- Um combinado pode embutir outro: uma linha so com o nome (`Forma`) traz as
  assinaturas dele. Combinado vazio aceita qualquer coisa (o `any` do Go).

## Type switch

`tipo()` de uma instancia devolve o **nome da treta**, entao o `escolhe` de
sempre vira o type switch:

```gambiarrascript
treta Circulo
    raio
acabou_finalmente
treta Retangulo
    largura
    altura
acabou_finalmente

gambiarra descreve(v)
    escolhe tipo(v)
    caso "Circulo"
        funciona "circulo de raio " + texto(v.raio)
    caso "Retangulo"
        funciona "retangulo " + texto(v.largura) + "x" + texto(v.altura)
    se_nao_colar
        funciona "sei la: " + tipo(v)
    acabou_finalmente
acabou_finalmente

mostra descreve(Circulo{2})         # circulo de raio 2
mostra descreve(Retangulo{3, 4})    # retangulo 3x4
mostra descreve("oi")               # sei la: texto
```

`tipo(Circulo)` (o tipo, nao uma instancia) e `"treta"`; `tipo(Forma)` e
`"combinado"`.

Quer os campos tambem? O padrao de treta do `escolhe` confere o tipo **e**
amarra os campos de uma vez (veja
[pattern matching](/docs/estruturas#pattern-matching-no-caso)):

```gambiarrascript
treta Ponto
    x
    y
acabou_finalmente

gambiarra onde(p)
    escolhe p
    caso Ponto{x: 0, y: 0}
        funciona "na origem"
    caso Ponto{x: 0, y}
        funciona "no eixo y, altura ${y}"
    caso Ponto{x, y} se x == y
        funciona "na diagonal"
    caso Ponto{_, _}
        funciona "em algum lugar"
    se_nao_colar
        funciona "nem e ponto"
    acabou_finalmente
acabou_finalmente

mostra onde(Ponto{0, 0})   # na origem
mostra onde(Ponto{0, 3})   # no eixo y, altura 3
mostra onde(Ponto{2, 2})   # na diagonal
mostra onde(42)            # nem e ponto
```

Com `campo:` e **por nome** (so os campos que voce listar; `y` sozinho e
`y: y`); sem nenhum `:` e **na ordem** dos campos, todos eles (igual o
literal).

## Puxadinho: composicao (embedding)

Uma linha da treta que e **so o nome de outra treta** encaixa ela dentro. Os
campos e metodos da de dentro **sobem** pra de fora (promotion) — estende sem
virar heranca.

```gambiarrascript
treta Animal
    nome = "anonimo"
    patas = 4
acabou_finalmente
gambiarra (a Animal) fala()
    funciona a.nome + " faz barulho"
acabou_finalmente
gambiarra (a Animal) apresenta()
    funciona "sou " + a.nome
acabou_finalmente

treta Cachorro
    Animal            # puxadinho
    raca = "vira-lata"
acabou_finalmente
gambiarra (c Cachorro) fala()
    funciona c.nome + " late"
acabou_finalmente

bota rex = Cachorro{Animal: Animal{nome: "rex"}}
mostra rex.nome              # rex (promovido)
mostra rex.fala()            # rex late (o do Cachorro esconde o do Animal)
mostra rex.Animal.fala()     # rex faz barulho (caminho explicito)
mostra rex.apresenta()       # sou rex (metodo promovido roda no Animal de dentro)
bota rex.patas = 3           # escreve no Animal de dentro
mostra rex                   # Cachorro{Animal: Animal{nome: "rex", patas: 3}, raca: "vira-lata"}
```

- O campo do puxadinho se chama como a treta (`rex.Animal`) e nasce com ela
  zerada. Ele so aceita uma instancia daquela treta.
- No literal o campo promovido nao vale direto: passe o puxadinho inteiro,
  `Cachorro{Animal: Animal{nome: "rex"}}` (ou na ordem: `Cachorro{Animal{"rex", 4}, "poodle"}`).
- Regra de conflito igual Go: o nome mais **raso** ganha; se o mesmo nome
  aparecer em dois puxadinhos na mesma profundidade, so da erro quando alguem
  acessar ele (use o caminho completo).

## cardapio (enum)

Um conjunto fechado de opcoes com nome: `cardapio Nome`, uma opcao por linha,
`acabou_finalmente`. Cada opcao e um valor proprio, acessado com ponto.

```gambiarrascript
cardapio Sinal
    verde
    amarelo
    vermelho
acabou_finalmente

gambiarra proximo(s)
    escolhe s
    caso Sinal.verde
        funciona Sinal.amarelo
    caso Sinal.amarelo
        funciona Sinal.vermelho
    caso Sinal.vermelho
        funciona Sinal.verde
    acabou_finalmente
acabou_finalmente

bota s = Sinal.verde
mostra s                     # Sinal.verde
mostra proximo(s)            # Sinal.amarelo
mostra tipo(s)               # Sinal
mostra s.nome                # verde
mostra s.indice              # 0
mostra s == Sinal.verde      # deu_bom
mostra s == "verde"          # deu_ruim
pra_cada op em Sinal
    mostra op.nome           # verde, amarelo, vermelho
acabou_finalmente
bota tempo = {Sinal.verde: 30, Sinal.vermelho: 20}
mostra tempo[Sinal.verde]    # 30
```

- A opcao so e igual a **ela mesma**: nao e numero nem texto (`Sinal.verde ==
  "verde"` e `deu_ruim`). Pra converter, use `.nome` (o texto) e `.indice`
  (a posicao, comecando em 0).
- `mostra` imprime `Sinal.verde`; `tipo()` da o nome do cardapio. O cardapio
  em si imprime `<cardapio Sinal>` e o `tipo()` dele e `"cardapio"`.
- `pra_cada op em Sinal` anda nas opcoes na ordem da declaracao (com dois
  nomes vem indice e opcao).
- Serve de chave de dicionario e item de conjunto. No `pra_json` vira o nome:
  `pra_json({"s": Sinal.verde})` e `{"s":"verde"}`.
- Opcao que nao existe (`Sinal.azul`) e erro na hora. Igual a treta: nome com
  maiuscula, declarado no **topo** do arquivo, e de outro modulo funciona com
  o alias (`m.Sinal.verde`).
- Funciona no `escolhe`, inclusive dentro de padrao (`caso [Sinal.verde, n]`).
  O `gs check` avisa o `escolhe` que so testa opcoes de um cardapio, esquece
  alguma e nao tem `se_nao_colar`.

## Percorrendo uma treta

`pra_cada x em instancia` chama o metodo **`itera()`** da treta e percorre o
que ele devolver: lista, dicionario, conjunto, cardapio ou **gerador**. Assim tua colecao
funciona em laco igual as da linguagem — com dois nomes (`pra_cada i, x em
caixa`) tambem, do mesmo jeito que o valor devolvido (lista e gerador: posicao
e valor; dicionario: chave e valor).

```gambiarrascript
treta Intervalo
    inicio
    fim
acabou_finalmente

gambiarra (r Intervalo) itera()
    bota i = r.inicio
    enquanto i <= r.fim
        rende i
        i += 1
    acabou_finalmente
acabou_finalmente

pra_cada x em Intervalo{1, 3}
    mostra x                    # 1, 2, 3
acabou_finalmente
mostra lista(Intervalo{5, 7})   # [5, 6, 7]
```

- O `itera()` roda **uma vez por laco**, quando o `pra_cada` comeca (com
  gerador, os valores saem sob demanda).
- `lista(instancia)` tambem usa o `itera()`.
- Treta sem `itera()` da erro claro: `a treta Caixa nao tem itera(), nao da pra
  percorrer`. Se o `itera()` devolver outra coisa (numero, outra treta...), o
  erro diz o que veio.
- O `itera()` de um puxadinho e promovido como qualquer metodo: a treta que
  embute uma percorrivel ja e percorrivel.

## Imprimir, comparar, JSON

- `mostra p` imprime `Ponto{x: 1, y: 2}` (texto com aspas, igual dicionario).
- `==` compara **campo a campo**: mesma treta e campos iguais (igual struct do
  Go). Treta diferente com os mesmos campos e diferente.
- `pra_json(p)` vira um objeto com os campos; o puxadinho e achatado, igual o
  `encoding/json` do Go: `{"nome":"rex","patas":3,"raca":"vira-lata"}`.
- `bota {x, y} = p` desestrutura pelos campos.
- Instancia nao serve de chave de dicionario nem item de conjunto.

## Concorrencia

A instancia e um objeto mutavel compartilhado, com a mesma garantia das
colecoes: cada leitura ou escrita de campo e atomica (nunca corrompe nem
derruba o processo, mesmo com `bora` e handlers do servidor mexendo junto).
Operacao **composta** (`p.x += 1`) nao e atomica — junte com
`com_trava(t, gambiarra() ... acabou_finalmente)` (veja
[Concorrencia](/docs/concorrencia)).
