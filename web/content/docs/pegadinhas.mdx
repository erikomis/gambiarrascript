## Atribuir dentro de funcao cria variavel local

Ler uma variavel de fora funciona; **atribuir** (`bota x = ...`, `x += ...`)
dentro de uma gambiarra cria uma variavel **local** com o mesmo nome — a de
fora fica igual (estilo Python sem `global`/`nonlocal`). Vale pra closure e
pra `bora` tambem.

```gambiarrascript
bota total = 0
gambiarra soma_no_total(x)
    total += x           # cria um "total" local (o gs check avisa)
    funciona total
acabou_finalmente

mostra soma_no_total(5)  # 5
mostra total             # 0
```

Pra estado compartilhado, use um dicionario/lista (passados por referencia) e
mude o conteudo: `estado.total += x`. Ou devolva o valor com `funciona`. O
`gs check` (e o editor) avisa quando uma gambiarra le um nome de fora antes de
botar nele — `x += ...` ou `bota x = x + ...` sem um `bota x = ...` antes.

O nome vira local na **funcao inteira**, nao so da linha do `bota` pra baixo.
Ler antes de botar enxerga o valor de fora — o escopo mais de dentro em que o
nome **ja tem valor** vale (local, depois a funcao de fora, depois a global,
depois o builtin). Num laco, a primeira volta le a global e as seguintes ja
leem o local:

```gambiarrascript
bota x = 1
gambiarra f()
    pra_cada i em [1, 2]
        mostra x          # 1, depois 11 (o gs check avisa)
        bota x = 10 + i
    acabou_finalmente
acabou_finalmente
f()
mostra x                  # 1
```

Nome que nao tem valor em lugar nenhum (o `bota` ficou num ramo que nao rodou)
da o erro ``cade o `y`? voce nao botou isso ainda``. E a gambiarra enxerga global
declarada **depois** dela — vale o que tiver na hora da chamada.

## Closure enxerga a variavel, nao uma copia

A gambiarra criada dentro de outra le a variavel de fora **na hora que roda**:
se a de fora mudar depois, a closure ve o valor novo. Closures criadas num
laco dividem a mesma variavel do `pra_cada` — todas veem o ultimo valor:

```gambiarrascript
gambiarra f()
    bota fs = []
    pra_cada i em [1, 2, 3]
        adiciona(fs, gambiarra() funciona i acabou_finalmente)
    acabou_finalmente
    funciona mapeia(fs, gambiarra(g) funciona g() acabou_finalmente)
acabou_finalmente
mostra f()                # [3, 3, 3]
```

Quer guardar o valor de cada volta? Monte a closure numa gambiarra separada
que recebe o valor como parametro — cada chamada tem a sua variavel:

```gambiarrascript
gambiarra fixa(v)
    funciona gambiarra() funciona v acabou_finalmente
acabou_finalmente

bota fs = []
pra_cada i em [1, 2, 3]
    adiciona(fs, fixa(i))
acabou_finalmente
mostra mapeia(fs, gambiarra(g) funciona g() acabou_finalmente)   # [1, 2, 3]
```

## Escopo do `pra_cada` e do `quebrou` (estilo Python)

A variavel do `pra_cada` e a da clausula `quebrou` **continuam existindo**
depois que o bloco fecha — elas vazam pro escopo da funcao que as contem.

```gambiarrascript
pra_cada fruta em ["caju", "goiaba"]
acabou_finalmente
mostra fruta          # goiaba (o ultimo item)

arruma
    bota x = 1 / 0
quebrou erro
    mostra "pegou"
acabou_finalmente
mostra erro_msg(erro) # ainda visivel
```

No `pra_cada i de A ate B`, `i` fica com o ultimo valor que rodou (`B`).

## Palavra-chave nao vira nome

`e`, `ou`, `nao`, `de`, `ate`, `em`, `como`, `entao`, `caso`, `escolhe`,
`finalmente`, `nada`, `cardapio`... sao palavras-chave. `quebrou e` ou
`bota de = 1` da erro de sintaxe. Use `quebrou erro`, `bota inicio = 1`.

## `caso x` compara, `caso [x]` amarra

No `escolhe`, nome solto **fora** de padrao continua sendo comparacao com a
variavel; so **dentro** de `[ ]`, `{ }` ou `Tipo{ }` o nome vira variavel
nova (e casa qualquer coisa):

```gambiarrascript
bota limite = 10
escolhe [3]
caso [limite]              # amarra: limite vira 3 (nao compara com 10!)
    mostra "casou, limite = ${limite}"
acabou_finalmente

bota alvo = 5
escolhe [5]
caso [n] se n == alvo      # pra comparar com variavel, use guarda
    mostra "e o alvo"
acabou_finalmente
```

E como o padrao amarra no escopo da funcao (igual `bota`), ele **troca** a
variavel de mesmo nome. Duas consequencias de quem escrevia `caso` com lista
ou dicionario antes do pattern matching:

- `caso [a, b]` era "igual a lista `[a, b]`"; agora casa **qualquer** lista de
  2 itens. Literal dentro continua comparando: `caso [1, 2]` segue igual.
- `caso {"tipo": "x"}` era igualdade do dicionario inteiro; agora e
  **subconjunto** (chave a mais no valor tambem casa).

## `bota` pra atribuir, mas `+=` dispensa

`x = 5` puro e erro de sintaxe: atribuicao simples sempre leva `bota`
(`bota x = 5`, `bota xs[0] = 5`, `bota obj.campo = 5`). Ja a atribuicao
composta (`x += 1`, `xs[0] *= 2`, `obj.n -= 1`, `x **= 2`) vem **sem** `bota`.
E nome declarado com `crava` nao aceita nenhuma das duas.

## `crava` nao e por bloco

O `crava` vale pro escopo da funcao (igual `bota`), nao pro bloco. Entao cravar
o mesmo nome nos dois lados de um `se_colar` conta como cravar duas vezes — e
da erro antes de rodar:

```gambiarrascript
bota modo = "producao"
# se_colar modo == "producao"
#     crava URL = "https://api.exemplo.com"
# se_nao_colar
#     crava URL = "http://localhost:8080"     -> erro: `URL` ja foi cravada
# acabou_finalmente

# use o ternario: um crava so
crava URL = se_colar modo == "producao" entao "https://api.exemplo.com" se_nao_colar "http://localhost:8080"
mostra URL                 # https://api.exemplo.com
```

Ja `crava` dentro do corpo de um laco pode: e o mesmo `crava` a cada volta.

## `-2 ** 2` e `-4`

O `**` prende mais que o menos da frente (igual Python): `-2 ** 2` e
`-(2 ** 2)`. Quer elevar o negativo? `(-2) ** 2` da `4`. E `2 ** 3 ** 2` e
`2 ** 9` (associa pela direita).

## `pi` da pra sombrear

`pi` e um valor pronto, nao palavra-chave: `bota pi = 3` cria uma variavel que
esconde o `pi` de verdade dali pra frente (igual acontece com qualquer
builtin). Quer garantir? `crava PI = pi` e use `PI`.

## `e` / `ou` sempre devolvem booleano

Diferente de JS e Python, `e`/`ou` no GambiarraScript **normalizam** o operando
pra `deu_bom`/`deu_ruim`:

```gambiarrascript
mostra "x" e "y"      # deu_bom  (nao devolve "y")
mostra nada ou "ok"   # deu_bom  (nao devolve "ok")
```

Pra "valor ou padrao", use `??`: `nome ?? "anonimo"`.

## Truthiness

So `nada` e `deu_ruim` sao falsy. **Tudo o mais** e truthy: `0`, `""`, `[]`, `{}`
inclusive. Se quiser checar vazio, faca explicitamente (`tamanho(x) == 0`,
`x == ""`, etc). E o `??` so troca `nada` — `0 ?? 5` continua `0`.

## Bitwise abaixo do `==`

Como em C, `&`, `|` e `^` tem precedencia **menor** que `==`: `x & 1 == 1` vira
`x & (1 == 1)` e da erro. Escreva `(x & 1) == 1`.

## Inteiro que estoura vira real

Inteiro e exato ate 64 bits. Conta que passa disso (`+`, `-`, `*`, o menos da
frente, `/`) **vira real** — nunca da a volta pro negativo nem trava no maximo:

```gambiarrascript
bota grande = 9223372036854775807   # maior inteiro de 64 bits
mostra grande + 1                     # 9223372036854776000 (real)
mostra grande * 2                     # 18446744073709552000
```

Real nao tem os digitos finais exatos, e operacao de bit (`&`, `|`, `^`, `~`,
`<<`, `>>`) em real da erro. Ja o `<<` entre inteiros so desloca os bits
(`1 << 64` e `0`), sem virar real.

## Divisao entre inteiros pode dar real

`7 / 2` e `3.5` (nao `3`). Quer divisao inteira? `chao(7 / 2)`.
E `/ 0` ou `% 0` da erro de runtime (nao `Inf`/`NaN`) — enrole num
`arruma...quebrou` se o divisor vier de fora.

## `pra_cada de ... ate` so sobe

`pra_cada i de 10 ate 1` nao roda nenhuma vez. Pra descer, use range:
`pra_cada i em 10..1`.

## `mostra` de lista nao poe aspas

```gambiarrascript
mostra ["1", 1]       # [1, 1] — texto e numero ficam iguais na tela
mostra pra_json(["1", 1])   # ["1",1]
```

Na duvida sobre o que tem dentro, use `pra_json`.

## Escapes e crase

So `\"`, `\\`, `\n` e `\t` escapam dentro de `"..."`. Qualquer outro `\x` e
mantido literal (barra e tudo). Pra texto cru (JSON, regex, path Windows),
use crase `` `...` `` — la nada e escapado... exceto o `${...}`, que **interpola
ate dentro da crase**. Tem `${` literal no texto? Use aspas duplas com `\${`.

## Goroutine solta morre com o script

`bora f()` sem `espera` e fire-and-forget: se o script principal terminar
antes, a goroutine morre junto (sem aviso). Veja [Concorrencia](/docs/concorrencia).

## Nada vs 0 vs ""

Sao coisas diferentes:

```gambiarrascript
mostra nada == 0      # deu_ruim
mostra nada == nada   # deu_bom
mostra "" == nada     # deu_ruim
```

## Botar `nada` nao apaga a chave

`bota d["k"] = nada` deixa a chave **la**, com valor `nada` — `tem(d, "k")`
continua `deu_bom` e ela aparece em `chaves(d)` e no `pra_cada`. Pra apagar de
verdade, `remove(d, "k")`.

```gambiarrascript
bota d = {"k": 1}
bota d["k"] = nada
mostra tem(d, "k")    # deu_bom
remove(d, "k")
mostra tem(d, "k")    # deu_ruim
```

## Ordem de avaliacao na chamada muda entre os motores

Numa chamada `f(args)`, o tree-walker (`gs roda --tree`) avalia **primeiro** o
que vai ser chamado e **depois** os argumentos; a VM (o padrao) faz o
contrario. So aparece quando as duas partes tem efeito colateral (imprimem,
mexem em estado...):

```gambiarrascript
gambiarra pega_f()
    mostra "pegou a funcao"
    funciona gambiarra(x) funciona x acabou_finalmente
acabou_finalmente

gambiarra arg()
    mostra "calculou o argumento"
    funciona 1
acabou_finalmente

pega_f()(arg())
# gs roda:        calculou o argumento / pegou a funcao
# gs roda --tree: pegou a funcao / calculou o argumento
```

Nao dependa dessa ordem: se importa, separa em dois `bota` antes de chamar.
