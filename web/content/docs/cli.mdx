O `gs` e o binario unico que faz tudo: roda, testa, formata, empacota e
conversa com o teu editor.

## Uso

```
gs roda [--tree] [--cache] <arquivo.gs> [args]   executa (VM e o padrao)
gs repl                                          modo interativo (multiline)
gs check <arquivo.gs>...                         parse + lint (erros e avisos)
gs formata [-w] <arquivo.gs | diretorio>...      formata (imprime ou sobrescreve)
gs testa [--tree] [-so nome] [<dir>]             roda os *_test.gs e soma os asserts
gs doc [<arquivo.gs | diretorio>...]             gera markdown das gambiarras documentadas
gs init [nome]                                   cria gambiarra.json + principal.gs
gs get <url> [nome.gs]                           baixa um modulo pra gs_modulos/
gs build <arquivo.gs> [-o saida]                 gera binario standalone com o script
gs bench [--tree] <arquivo.gs> [n]               mede o tempo de execucao (n rodadas)
gs disasm <arquivo.gs>                           mostra o bytecode da VM
gs lsp                                           language server (usado pelo editor)
gs --version  (ou gs versao)                     mostra a versao
gs --help                                        mostra a ajuda
```

## `gs roda`

```bash
gs roda [--tree] [--cache] <arquivo.gs> [args...]
```

- Roda o arquivo na **VM de bytecode** — o motor padrao (o mesmo do `build`,
  `testa`, `bench`, REPL e playground).
- `--tree` volta pro interpretador tree-walking (fallback; os dois motores
  rodam todos os exemplos igual). `--vm` ainda e aceito por compatibilidade,
  mas nao muda nada.
- `--cache` grava o bytecode compilado em `arquivo.gsc` do lado do `.gs` e
  reaproveita nas proximas vezes (invalida sozinho quando a fonte, a versao do
  `gs` ou a lista de builtins muda). Nao se aplica com `--tree`.
- Tudo depois do arquivo vira argumento acessivel via `argumentos()`.
- `importa` resolve caminho relativo ao diretorio do arquivo rodado.

```bash
gs roda exemplo.gs              # roda na VM
gs roda --tree exemplo.gs       # roda no tree-walker
gs roda --cache exemplo.gs      # grava/usa exemplo.gsc
gs roda script.gs prim seg      # argumentos() == [prim, seg]
```

Codigo de saida: erro de sintaxe (ou nome que nao existe, `vaza` fora de laco)
e pego **antes** de rodar → `exit 1`. Erro de runtime nao tratado imprime a
mensagem + traco de pilha → `exit 1`. `sai(n)` sai com `n`.

## `gs repl`

```bash
gs repl
```

Abre o modo interativo (roda na VM). Detalhes:

- **Multiline**: abriu um bloco (`se_colar`, `gambiarra`, `pra_cada`,
  `escolhe`...) o prompt vira `.........` ate fechar o `acabou_finalmente`.
- Expressao solta mostra o valor com `=> valor` (a nao ser que seja `nada`).
- Declaracoes (`bota`, `gambiarra`) persistem entre as linhas.
- No terminal: historico com ↑/↓, edicao de linha e **TAB** completa
  builtins, palavras-chave e variaveis.
- Comandos: `:ajuda` e `:limpa`. `ctrl+d` vaza.

```bash
gambiarra> bota x = 10
gambiarra> x * 2
=> 20
gambiarra> gambiarra dobra(n)
.........     funciona n * 2
......... acabou_finalmente
gambiarra> dobra(x)
=> 20
gambiarra> <ctrl+d>
```

## `gs check`

```bash
gs check arquivo.gs outro.gs
```

Parseia e passa o lint (o mesmo typechecker do LSP) sem rodar nada. Mostra
`arquivo:linha:coluna: erro: ...` / `aviso: ...`. Mexer num nome cravado
(`crava`) e erro. Avisos: nome que nao existe,
variavel `bota` declarada e nunca usada, codigo morto depois de
`funciona`/`vaza`/`continua`. Sai com `1` so quando tem erro de sintaxe.

```bash
$ gs check exemplo.gs
exemplo.gs:15:14: aviso: `nome` foi declarada mas nunca usada
$ gs check ok.gs
ok.gs: suave, zero perrengue
```

## `gs formata`

```bash
gs formata <arquivo.gs | dir>...        # imprime formatado no stdout
gs formata -w <arquivo.gs | dir>...     # sobrescreve (so se mudou algo)
gs formata -w .                         # todos os .gs da pasta, recursivo
```

Indenta com 4 espacos e normaliza o espacamento, mantendo comentarios e
linhas em branco. Com `-w`, so grava se o resultado tiver o mesmo codigo e os
mesmos comentarios — senao avisa `NAO formatado` e deixa o arquivo como
estava. Mais em [Editor e formata](/docs/ferramentas#formatter-gs-formata).

## `gs testa`

```bash
gs testa [--tree] [-so nome] [<dir>]
```

Roda cada `*_test.gs` do diretorio (default: o atual; nao entra em
subpastas). Dentro dos testes, os asserts sao `espera(recebido, esperado)` e
`afirma(condicao, [mensagem])`. `-so nome` (ou `--somente`) filtra pelos
arquivos cujo nome contem `nome`. Sai com `1` se algum assert falhar.

```gambiarrascript
# soma_test.gs
gambiarra soma(a, b)
    funciona a + b
acabou_finalmente

espera(soma(2, 2), 4)
afirma(soma(1, 1) == 2, "um mais um")
```

```bash
$ gs testa
rodando 1 arquivo(s) no VM:
  OK  soma_test.gs  (2/2 asserts)

Resumo (VM): 1 arquivos, 2/2 asserts passaram, 0 com perrengue
```

## `gs doc`

```bash
gs doc [<arquivo.gs | dir>...]
```

Gera markdown no stdout: pra cada `gambiarra` e cada `crava` de topo, a
assinatura e o bloco de comentarios `#` logo acima.

## `gs init`

```bash
gs init meu_app
```

Cria `gambiarra.json` (nome, versao, principal, dependencias) e um
`principal.gs` de hello world. Nunca sobrescreve arquivo existente.

## `gs get`

```bash
gs get https://exemplo.com/util.gs [nome.gs]
```

Baixa o modulo, confere se parseia, salva em `gs_modulos/` e registra em
`dependencias` no `gambiarra.json`. Sem versao/lockfile ainda. Veja
[Modulos](/docs/modulos).

## `gs build`

```bash
gs build app.gs -o app
./app arg1 arg2
```

Gera um binario standalone: o proprio `gs` com o teu script embutido (roda na
VM). Quem receber nao precisa ter o `gs` instalado — so precisa ser o mesmo
sistema operacional/arquitetura. No macOS ele tenta re-assinar o binario
(ad-hoc); se nao conseguir, avisa o comando `codesign` pra rodar.

## `gs bench`

```bash
gs bench [--tree] arquivo.gs [n]
```

Roda o script `n` vezes (default 10), descartando a saida, e mostra
min/mediana/media/max.

## `gs disasm`

```bash
gs disasm arquivo.gs
```

Mostra o bytecode que a VM vai executar. Bom pra curiosidade.

## `gs lsp`

Roda o servidor LSP no stdin/stdout (JSON-RPC): diagnosticos, autocomplete,
hover, ir pra definicao, referencias, renomear, outline, ajuda de assinatura e
formatar documento. Nao e pra voce rodar direto — voce configura no editor. Veja [Editor e formata](/docs/ferramentas).

## `gs --version` / `gs --help`

```bash
gs --version
# gs (GambiarraScript) 0.1.0
```

`versao`, `version`, `-v`, `ajuda` e `-h` tambem valem.

## Argumentos no script

Qualquer coisa depois do arquivo vira `argumentos()` no runtime:

```gambiarrascript
# args.gs
mostra "recebi ${tamanho(argumentos())} argumentos:"
pra_cada arg em argumentos()
    mostra "  - " + arg
acabou_finalmente
```

```bash
$ gs roda args.gs a b c
recebi 3 argumentos:
  - a
  - b
  - c
```

`argumentos()` e uma lista de textos. Use `numero(arg)` pra converter numeros.

## Exemplos pra rodar

O repo vem com `examples/` prontos:

```bash
gs roda examples/salve.gs
gs roda examples/fizzbuzz.gs
gs roda examples/tier3.gs         # bitwise, range, interpolacao, finalmente
gs roda examples/maturidade.gs    # escolhe, lambdas, destructuring, formata
gs roda examples/libs.gs          # regex, tempo, crypto, conjunto
gs roda examples/stats.gs         # soma, media, zip, ordena_por, agrupa_por
gs roda examples/banco.gs         # sqlite em memoria
gs roda examples/servidor.gs      # sobe um servidor HTTP na 8080
gs roda examples/http.gs          # chama uma API publica
```

Olha `examples/` no repo — sao scripts curtos, boas fontes de ideias.
