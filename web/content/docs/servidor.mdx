## rota(metodo, caminho, handler)

Registra uma rota. O caminho pode ter **parametros** e um **curinga** no fim:

| padrao              | casa com                    | `pedido["params"]`              |
| ------------------- | --------------------------- | ------------------------------- |
| `/usuarios`         | so `/usuarios`              | `{}`                            |
| `/usuarios/:id`     | `/usuarios/42`              | `{"id": "42"}`                  |
| `/u/:id/posts/:p`   | `/u/7/posts/9`              | `{"id": "7", "p": "9"}`         |
| `/arquivos/*resto`  | `/arquivos/css/site.css`    | `{"resto": "css/site.css"}` (pode vir `""`) |

- Parametro casa **um** pedaco nao-vazio, ja desescapado (`%2F` vira `/`
  dentro do valor, sem rachar a rota). Valor sempre texto.
- Quando mais de uma rota casa, ganha a mais especifica: pedaco fixo ganha de
  parametro, que ganha de curinga (`/usuarios/eu` ganha de `/usuarios/:id`).
- Nada casou → `404 rota nao encontrada, parca`. O caminho existe com outro
  metodo → `405` com o cabecalho `Allow` (ex.: `Allow: DELETE, GET, HEAD`).
- `HEAD` sem rota propria usa a de `GET` (sem corpo).
- Registrar de novo o mesmo metodo + caminho troca o handler.

O `handler` e uma `gambiarra` (com nome ou lambda). Pode declarar menos
parametros do que recebe: `gambiarra() funciona "ok" acabou_finalmente` vale.
Ele recebe o dicionario `pedido`:

| chave        | tipo  | conteudo                                          |
| ------------ | ----- | ------------------------------------------------- |
| `metodo`     | texto | metodo HTTP (`"GET"`, `"POST"`...)                |
| `caminho`    | texto | path da URL (`"/usuarios/42"`)                    |
| `corpo`      | texto | corpo cru do request                              |
| `cabecalhos` | dic   | headers, com o nome canonico do Go (`Content-Type`, `X-Teste`) |
| `query`      | dic   | query string (`?nome=ze` → `pedido.query.nome`)   |
| `params`     | dic   | parametros do caminho (`:id`, `*resto`)           |
| `json`       | valor | corpo ja parseado quando o `Content-Type` e `application/json` (ou `...+json`); `nada` se nao for JSON ou vier vazio |
| `ip`         | texto | IP de quem pediu (o da conexao; atras de proxy, leia `X-Forwarded-For` nos cabecalhos) |
| `cookies`    | dic   | cookies do request (`nome → valor`)               |

Header ou parametro de query repetido chega junto com `", "`.

**JSON quebrado** com `Content-Type: application/json` nem chega no handler:
o servidor responde `400` com `esse json do corpo ta quebrado, parca: <onde>`.
Quer tratar na mao? Mande outro `Content-Type` e use `de_json(pedido.corpo)`
dentro de `arruma`.

## Resposta

O handler devolve:

| devolveu | resposta |
| -------- | -------- |
| texto | `200` com o texto |
| `nada` | `200` com corpo vazio |
| lista | `200` com a lista em JSON (`Content-Type: application/json; charset=utf-8`) |
| dicionario **de resposta** | `{"status": numero, "corpo": ..., "cabecalhos": dic}` — tudo opcional |
| qualquer outro dicionario | `200` com o dicionario em JSON |

Dicionario **de resposta** e o que so tem as chaves `status`, `corpo` e/ou
`cabecalhos` (com `status` numero e `cabecalhos` dicionario). O resto e dado:
`{"status": "ok"}` (status texto) e `{"corpo": 1, "id": 2}` viram JSON. Na
duvida, seja explicito com `responde_json`.

- `status` fora de 100–599 vira `500`.
- `corpo` lista/dicionario vira JSON (e ganha o `Content-Type` de JSON se voce
  nao mandou outro).
- Valor de cabecalho pode ser texto, numero, booleano ou **lista** de textos
  (varias linhas do mesmo cabecalho — e assim que se manda dois cookies).

```gambiarrascript
rota("POST", "/login", gambiarra(pedido)
    funciona {
        "status": 204,
        "cabecalhos": {"Set-Cookie": ["sessao=abc; Path=/; HttpOnly", "tema=escuro; Path=/"]}
    }
acabou_finalmente)
```

### responde_json(valor, [status])

Monta a resposta JSON pronta: `{"status": status, "corpo": pra_json(valor),
"cabecalhos": {"Content-Type": "application/json; charset=utf-8"}}`. Status
default `200`; tem que ser inteiro de 100 a 599.

```gambiarrascript
rota("GET", "/usuarios/:id", gambiarra(pedido)
    se_colar pedido.params.id != "1"
        funciona responde_json({"erro": "nao achei"}, 404)
    acabou_finalmente
    funciona {"id": 1, "nome": "Ze"} # dicionario de dado: JSON 200
acabou_finalmente)
```

### Erro no handler

Se o handler (ou um middleware) estoura um erro, o cliente recebe **`500`**
com o corpo generico `deu ruim no servidor (erro interno), parca` — nada de
vazar mensagem interna. O erro completo (mensagem com linha e traço de
pilha) vai pro **stderr**, e o servidor segue atendendo:

```
servidor: GET /usuarios/abc estourou em <rota GET /usuarios/:id>
  deu ruim na linha 12: nao da pra dividir por zero, parca — nem na gambiarra
```

## Validando o corpo

O `pedido.json` chega parseado, mas do jeito que o cliente mandou. O
`valida(valor, esquema)` confere o formato e devolve a **lista de erros**,
cada um com o caminho do campo — vazia quando ta tudo certo. Responde `400`
com ela e o cliente sabe exatamente o que arrumar:

```gambiarrascript
crava ESQUEMA_TAREFA = {
    "titulo": {"tipo": "texto", "min": 1, "max": 200},
    "feita": "booleano?",
    "prazo": "data?",
    "etiquetas": {"tipo": "lista", "obrigatorio": deu_ruim, "itens": "texto"},
    "_estrito": deu_bom,
}

rota("POST", "/tarefas", gambiarra(pedido)
    bota erros = valida(pedido.json, ESQUEMA_TAREFA)
    se_colar tamanho(erros) > 0
        funciona responde_json({"erros": erros}, 400)
    acabou_finalmente
    # daqui pra baixo o corpo tem o formato certo
    funciona responde_json({"titulo": pedido.json.titulo}, 201)
acabou_finalmente)
```

```bash
curl -X POST localhost:8080/tarefas -H "Content-Type: application/json" \
     -d '{"titulo": 3, "etiquetas": ["casa", 7], "cor": "azul"}'
# 400 {"erros":["titulo: tem que ser texto, veio numero","etiquetas[1]: tem que ser texto, veio numero","cor: campo nao esperado"]}
```

- Corpo vazio (`pedido.json` e `nada`) da `["obrigatorio"]`; JSON quebrado
  nem chega no handler (o servidor ja responde `400`).
- `"texto?"` e opcional; sem `?` o campo e obrigatorio (faltar ou vir `null`
  conta como faltando).
- `"_estrito": deu_bom` recusa campo que o esquema nao conhece — bom pra
  pegar erro de digitacao do cliente (`"titlo"`).
- As regras (`min`, `max`, `padrao`, `opcoes`, `itens`, `campos`) estao em
  [Biblioteca → Validacao](/docs/biblioteca#validacao).

O `examples/api_rest.gs` valida o POST e o PUT desse jeito.

## Middleware: antes() e depois()

`antes(gambiarra(pedido) ...)` roda antes de **toda rota** (inclusive
`rota_ws`), na ordem de registro:

- devolveu `nada` → segue pro proximo middleware e depois pra rota;
- devolveu qualquer outra coisa → **essa e a resposta**, a rota nem roda;
- pode mexer no `pedido` (`bota pedido["usuario"] = ...`) e o handler ve.

`depois(gambiarra(pedido, resposta) ...)` roda depois, com a resposta ja
normalizada em `{"status", "corpo", "cabecalhos"}`. Devolveu `nada` → vale a
resposta (inclusive se voce mexeu nela no lugar); devolveu outra coisa → troca.
Bom pra log e cabecalho padrao.

Middleware so roda em pedido que casou com rota (404/405 e arquivo estatico
passam direto).

```gambiarrascript
antes(gambiarra(pedido)
    se_colar pedido.cabecalhos["Authorization"] != "Bearer segredo"
        funciona responde_json({"erro": "sem token"}, 401)
    acabou_finalmente
    bota pedido["usuario"] = "admin"
acabou_finalmente)

depois(gambiarra(pedido, resposta)
    mostra "${pedido.metodo} ${pedido.caminho} -> ${resposta.status}"
    bota resposta["cabecalhos"]["X-Servidor"] = "gambiarra"
acabou_finalmente)
```

## cors([opcoes])

Liga CORS no servidor todo: responde o preflight (`OPTIONS` com
`Access-Control-Request-Method`) com `204` e poe
`Access-Control-Allow-Origin` nas respostas pra origem liberada.

```gambiarrascript
cors() # qualquer origem

cors({
    "origens": ["https://meusite.com"],
    "metodos": ["GET", "POST"],
    "cabecalhos": ["Authorization", "Content-Type"],
    "credenciais": deu_bom,
    "max_idade": 600
})
```

| opcao | default | |
| ----- | ------- | - |
| `origens` | `["*"]` | lista de origens exatas (`"https://x.com"`); `"*"` libera geral |
| `metodos` | `GET, POST, PUT, PATCH, DELETE, OPTIONS` | |
| `cabecalhos` | o que o navegador pediu | `Access-Control-Allow-Headers` |
| `credenciais` | `deu_ruim` | com `deu_bom`, manda `Allow-Credentials` e ecoa a origem — **exige lista de `origens`** |
| `max_idade` | `600` | segundos de cache do preflight |

Preflight de origem nao liberada leva `403`. Chamar `cors()` de novo troca a
configuracao. Opcao com nome errado da erro.

`credenciais` com qualquer origem (`cors({"credenciais": deu_bom})`) e erro de
proposito: o navegador manda o cookie junto, entao liberar geral com
credenciais deixa **qualquer site** fazer pedido logado em nome do teu
usuario. Lista as origens que podem.

## serve_pasta(prefixo, pasta)

Serve arquivos estaticos debaixo do prefixo (so `GET`/`HEAD`):

```gambiarrascript
serve_pasta("/publico", "./public") # /publico/css/site.css → ./public/css/site.css
serve_pasta("/", "./site")          # site estatico inteiro
```

- Pasta → `index.html` dela (sem `index.html` da `404`: nada de listar
  conteudo). `/publico` sem barra redireciona pra `/publico/`.
- `Content-Type` pela extensao, `Range` e `If-Modified-Since` funcionam.
- Seguranca: `..` nao sai da pasta, symlink pra fora nao vale e arquivo/pasta
  com ponto na frente (`.env`, `.git`) nao e servido.
- `rota()` registrada no mesmo caminho ganha da pasta. O caminho da pasta e
  relativo a onde o `gs` foi rodado.

## escuta(porta, [opcoes])

Sobe o servidor e **bloqueia**. Aceita numero (`8080`) ou texto com o
endereco (`":8080"`, `"127.0.0.1:3000"`, `"0"`/`"127.0.0.1:0"` = porta livre
qualquer). Mostra no **stderr** o endereco de verdade:

```
servidor de pe em http://localhost:8080 (ctrl+c pra parar)
```

- **ctrl+c / SIGTERM** desliga com calma: para de aceitar conexao, espera ate
  5s os pedidos em andamento, avisa os WebSockets ("going away") e o
  `escuta` **volta** — o codigo depois dele roda (feche banco, salve estado).
  Um segundo ctrl+c mata na hora.
- Timeouts: 10s pra chegar o cabecalho do pedido, 60s pra ler o corpo, 120s
  de conexao ociosa (keep-alive).

Cada requisicao roda **em paralelo** (uma goroutine por pedido). Por isso,
cuidado ao mexer em lista/dicionario compartilhado entre handlers (veja
[Concorrencia](/docs/concorrencia#estado-compartilhado)): cada operacao
numa colecao e atomica, mas conta composta (`bota d["n"] = d["n"] + 1`) pede
`com_trava(trava, gambiarra() ... acabou_finalmente)`.

## HTTPS: `escuta(porta, {"tls": ...})`

```gambiarrascript
rota("GET", "/", gambiarra() funciona "salve, seguro" acabou_finalmente)
escuta(8443, {"tls": {"cert": "cert.pem", "chave": "chave.pem"}})
```

```
servidor de pe em https://localhost:8443 (ctrl+c pra parar)
```

- `cert` e `chave` sao os arquivos **PEM** do certificado (com a cadeia, se
  tiver intermediario — o `fullchain.pem` do Let's Encrypt) e da chave
  privada. Texto que comeca com `-----BEGIN` e tratado como o proprio PEM
  (veja `gera_certificado` abaixo).
- O certificado e lido **antes** de abrir a porta: arquivo que nao existe ou
  que nao e PEM valido (ou chave de outro certificado) da erro do tipo `"io"`
  na hora, com o caminho na mensagem — nada de servidor de pe que derruba
  todo handshake.
- TLS **1.2 no minimo**; suites e curvas ficam no padrao do Go (so as
  seguras). HTTP/2 vem de brinde pra quem pedir.
- **`rota_ws` vira `wss://`** sozinho: mesma porta, mesmo certificado.
- Tudo o resto (rotas, middleware, desligamento com calma, timeouts) e igual.
  Cliente falando `http://` na porta https ou que nao confia no certificado
  nao polui o stderr: o erro aparece do lado dele.

<Callout title="Em producao">
  Muitas vezes o TLS termina **antes** do teu servidor: um proxy reverso
  (nginx, Caddy, Traefik) ou o load balancer da nuvem segura o certificado
  (e renova sozinho) e repassa HTTP puro pro `escuta(8080)` na rede interna.
  Nesse caso nao precisa do `{"tls": ...}` — e o IP do cliente vem no
  cabecalho `X-Forwarded-For`. O `tls` aqui e pra quando o `gs` fica exposto
  direto, ou pra testar `https://`/`wss://` em casa.
</Callout>

### gera_certificado([hosts]) — so pra desenvolvimento

```gambiarrascript
bota par = gera_certificado()      # {"cert": "-----BEGIN CERTIFICATE-----...", "chave": "-----BEGIN PRIVATE KEY-----..."}
escreve_arquivo("cert.pem", par.cert) # pro curl --cacert / outro cliente confiar
escuta(8443, {"tls": par})         # o PEM em si vale no lugar do caminho
```

Gera um certificado **autoassinado** (ECDSA P-256, vale 1 ano) e devolve
`{"cert", "chave"}` em PEM. Hosts padrao: `localhost`, `127.0.0.1` e `::1`;
passe outros com `gera_certificado(["meu.dev", "192.168.0.10"])` (IP vira IP,
o resto vira nome). Ele e o proprio CA, entao o cliente confia passando o
`cert` como `ca`: `busca(url, {"ca": par.cert})` ou `curl --cacert cert.pem`.

<Callout title="Nao use em producao">
  Navegador nenhum confia nesse certificado (vai mostrar aviso). Em producao
  use um certificado de verdade (Let's Encrypt, o do teu provedor) ou deixe o
  proxy reverso cuidar do TLS. A chave sai em texto: nao commite o `chave.pem`.
</Callout>

## WebSocket: rota_ws(caminho, handler, [opcoes])

Com `escuta(porta, {"tls": ...})` o mesmo endpoint atende `wss://`.

```gambiarrascript
bota conexoes = []

rota_ws("/chat", gambiarra(ws, pedido)
    adiciona(conexoes, ws)
    enquanto deu_bom
        bota msg = recebe(ws) # bloqueia; nada = o cliente saiu
        se_colar msg == nada
            vaza
        acabou_finalmente
        pra_cada c em conexoes
            envia(c, {"de": pedido.query.nome, "texto": msg})
        acabou_finalmente
    acabou_finalmente
    remove(conexoes, ws)
acabou_finalmente)

escuta(8080)
```

- O handler roda **uma vez por conexao**, na goroutine dela, e recebe a
  conexao `ws` e o mesmo `pedido` das rotas HTTP (`params`, `query`,
  `cabecalhos`, `cookies`...). Caminho aceita `:param`/`*curinga`.
- `antes()` roda antes do handshake: devolver resposta (ex.: `401`) recusa a
  conexao.
- `recebe(ws)` bloqueia ate a proxima mensagem e devolve **texto**. Devolve
  `nada` quando o cliente fechou, caiu ou o servidor esta desligando — e o
  sinal pra sair do laco.
- `envia(ws, x)`: texto vai como esta; **lista/dicionario vao como JSON**
  (`pra_json`); numero/booleano viram texto. Pode chamar da mesma conexao em
  varias goroutines ao mesmo tempo (o envio e serializado por conexao).
  Mandar pra conexao que **ja caiu nao estoura** (a mensagem se perde) — o
  broadcast nao quebra por causa de um cliente que saiu. Mandar depois de
  voce mesmo chamar `fecha(ws)` e erro. Cliente que nao le por 10s e
  derrubado.
- `fecha(ws)` fecha (idempotente). Quando o handler termina, a conexao fecha
  sozinha; se ele estourar erro, fecha com codigo 1011 e o erro vai pro stderr.
- Keepalive: o servidor manda ping a cada 30s enquanto alguem esta no
  `recebe`; sem pong em 15s a conexao e derrubada e o `recebe` devolve `nada`.
- Origem: por padrao so aceita navegador da **mesma origem**. O handshake leva
  o cookie de qualquer site, entao liberar origem no websocket e liberar o
  login do usuario pra ela — por isso o `cors()` aberto **nao** vale aqui.
  Pra liberar, lista na propria rota: `rota_ws("/chat", h, {"origens":
  ["https://app.com"]})`; `["*"]` libera qualquer uma (so faz isso se o
  socket nao depender de login). Um `cors()` com lista de origens tambem
  vale. Cliente fora do navegador (sem `Origin`) sempre entra.
- Mensagem de ate 1 MiB.

`GET` normal (sem upgrade) numa `rota_ws` leva `426`.

### conecta_ws(url, [opcoes]) — cliente

```gambiarrascript
bota ws = conecta_ws("ws://localhost:8080/chat?nome=ze", {"cabecalhos": {"Authorization": "Bearer x"}, "timeout": 5})
envia(ws, "salve")
mostra recebe(ws)
fecha(ws)
```

Mesma conexao do servidor: `envia`/`recebe`/`fecha` funcionam igual.
`timeout` (segundos, default 30) vale so pra conectar. `wss://` valida o
certificado contra os CAs do sistema; pra falar com servidor de dev de
certificado proprio, `{"ca": "cert.pem"}` (caminho ou o PEM em si — com ele so
esse CA vale) ou, em ultimo caso, `{"inseguro": deu_bom}` — mesmas opcoes do
[`busca`](/docs/http#https-com-certificado-proprio-ca-e-inseguro). Falhou → erro de rede
(`conecta_ws(): nao consegui conectar em "ws://..." (o servidor respondeu 401): ...`).
WebSocket nao roda no playground (navegador).
