```gambiarrascript
gambiarra ola(pedido)
    funciona "salve, " + pedido["caminho"]
acabou_finalmente

rota("GET", "/", ola)
escuta(8080)
```

`rota` is a "route", `escuta` means "listen" and `pedido` is the incoming
"request". Full examples: `examples/api_rest.gs` (CRUD with auth and CORS),
`examples/chat_ws.gs` (chat with WebSocket broadcast) and `examples/upload.gs`
(upload + session + rate limit + gzip).

## rota(metodo, caminho, handler)

Registers a route. The path can have **parameters** and a **wildcard** at the end:

| pattern             | matches                     | `pedido["params"]`              |
| ------------------- | --------------------------- | ------------------------------- |
| `/usuarios`         | only `/usuarios`            | `{}`                            |
| `/usuarios/:id`     | `/usuarios/42`              | `{"id": "42"}`                  |
| `/u/:id/posts/:p`   | `/u/7/posts/9`              | `{"id": "7", "p": "9"}`         |
| `/arquivos/*resto`  | `/arquivos/css/site.css`    | `{"resto": "css/site.css"}` (may be `""`) |

- A parameter matches **one** non-empty segment, already unescaped (`%2F`
  becomes `/` inside the value without splitting the route). The value is
  always text.
- When more than one route matches, the most specific one wins: a fixed
  segment beats a parameter, which beats a wildcard (`/usuarios/eu` beats
  `/usuarios/:id`).
- Nothing matched → `404 rota nao encontrada, parca`. The path exists with a
  different method → `405` with the `Allow` header (e.g.
  `Allow: DELETE, GET, HEAD`).
- `HEAD` without a route of its own uses the `GET` one (without a body).
- Registering the same method + path again swaps the handler.

The `handler` is a `gambiarra` (named or a lambda). It may declare fewer
parameters than it receives: `gambiarra() funciona "ok" acabou_finalmente` is
fine. It gets the `pedido` dictionary:

| key          | type  | contents                                          |
| ------------ | ----- | ------------------------------------------------- |
| `metodo`     | text  | HTTP method (`"GET"`, `"POST"`...)                |
| `caminho`    | text  | URL path (`"/usuarios/42"`)                       |
| `corpo`      | text  | raw request body                                  |
| `cabecalhos` | dict  | headers, with Go's canonical name (`Content-Type`, `X-Teste`) |
| `query`      | dict  | query string (`?nome=ze` → `pedido.query.nome`)   |
| `params`     | dict  | path parameters (`:id`, `*resto`)                 |
| `json`       | value | body already parsed when the `Content-Type` is `application/json` (or `...+json`); `nada` if it isn't JSON or is empty |
| `ip`         | text  | the caller's IP (from the connection; behind a proxy, read `X-Forwarded-For` in the headers) |
| `cookies`    | dict  | request cookies (`name → value`)                  |
| `campos`     | dict  | form fields (`application/x-www-form-urlencoded` or `multipart/form-data`); a repeated field becomes a list |
| `arquivos`   | dict  | `multipart/form-data` files: `field → {"nome", "tipo", "tamanho", "conteudo_base64"}` (a list if the field repeats) |
| `sessao`     | dict  | only with `usa_sessao()`: the user's session (see below) |

A repeated header or query parameter arrives joined with `", "`.

**Broken JSON** with `Content-Type: application/json` never even reaches the
handler: the server answers `400` with `esse json do corpo ta quebrado, parca: <onde>`.
Want to handle it yourself? Send a different `Content-Type` and use
`de_json(pedido.corpo)` inside `arruma` ("fix it").

## Response

The handler returns:

| returned | response |
| -------- | -------- |
| text | `200` with the text |
| `nada` | `200` with an empty body |
| list | `200` with the list as JSON (`Content-Type: application/json; charset=utf-8`) |
| **response** dictionary | `{"status": numero, "corpo": ..., "cabecalhos": dic}` — all optional |
| any other dictionary | `200` with the dictionary as JSON |

A **response** dictionary is one that only has the keys `status`, `corpo`
and/or `cabecalhos` (with `status` a number and `cabecalhos` a dictionary).
Anything else is data: `{"status": "ok"}` (text status) and
`{"corpo": 1, "id": 2}` become JSON. When in doubt, be explicit with
`responde_json`.

- A `status` outside 100–599 becomes `500`.
- A list/dictionary `corpo` becomes JSON (and gets the JSON `Content-Type` if
  you didn't send another one).
- A header value can be text, a number, a boolean or a **list** of texts
  (several lines of the same header — that's how you send two cookies).

```gambiarrascript
rota("POST", "/login", gambiarra(pedido)
    funciona {
        "status": 204,
        "cabecalhos": {"Set-Cookie": ["sessao=abc; Path=/; HttpOnly", "tema=escuro; Path=/"]}
    }
acabou_finalmente)
```

### responde_json(valor, [status])

Builds a ready-made JSON response: `{"status": status, "corpo": pra_json(valor),
"cabecalhos": {"Content-Type": "application/json; charset=utf-8"}}`. Status
defaults to `200`; it must be an integer from 100 to 599.

```gambiarrascript
rota("GET", "/usuarios/:id", gambiarra(pedido)
    se_colar pedido.params.id != "1"
        funciona responde_json({"erro": "nao achei"}, 404)
    acabou_finalmente
    funciona {"id": 1, "nome": "Ze"} # data dictionary: JSON 200
acabou_finalmente)
```

### responde_html(html, [status])

Same thing for pages: returns the response dictionary with `html` as the
`corpo` and the header `Content-Type: text/html; charset=utf-8` (status
defaults to `200`). Pair it with [templates](/docs/en/modelos), which escape
the HTML for you:

```gambiarrascript
rota("GET", "/ola/:nome", gambiarra(pedido)
    funciona responde_html(renderiza("<h1>Salve, {{ nome }}!</h1>", pedido.params))
acabou_finalmente)
```

### Error in the handler

If the handler (or a middleware) blows up with an error, the client gets a
**`500`** with the generic body `deu ruim no servidor (erro interno), parca` —
no leaking internal messages. The full error (message with line number and
stack trace) goes to **stderr**, and the server keeps serving:

```
servidor: GET /usuarios/abc estourou em <rota GET /usuarios/:id>
  deu ruim na linha 12: nao da pra dividir por zero, parca — nem na gambiarra
```

## Validating the body

`pedido.json` arrives parsed, but exactly as the client sent it.
`valida(valor, esquema)` checks the shape and returns the **list of errors**,
each one prefixed with the field path — empty when everything is fine. Answer
`400` with it and the client knows exactly what to fix:

```gambiarrascript
crava ESQUEMA_TAREFA = {
    "titulo": {"tipo": "texto", "min": 1, "max": 200},
    "feita": "booleano?",
    "prazo": "data?",
    "etiquetas": {"tipo": "lista", "obrigatorio": deu_ruim, "itens": "texto"},
    "_estrito": deu_bom,
}

rota("POST", "/tarefas", gambiarra(pedido)
    bota erros = valida(pedido.json, ESQUEMA_TAREFA)
    se_colar tamanho(erros) > 0
        funciona responde_json({"erros": erros}, 400)
    acabou_finalmente
    # from here on the body has the right shape
    funciona responde_json({"titulo": pedido.json.titulo}, 201)
acabou_finalmente)
```

```bash
curl -X POST localhost:8080/tarefas -H "Content-Type: application/json" \
     -d '{"titulo": 3, "etiquetas": ["casa", 7], "cor": "azul"}'
# 400 {"erros":["titulo: tem que ser texto, veio numero","etiquetas[1]: tem que ser texto, veio numero","cor: campo nao esperado"]}
```

- An empty body (`pedido.json` is `nada`) gives `["obrigatorio"]`; broken
  JSON never reaches the handler (the server already answers `400`).
- `"texto?"` is optional; without `?` the field is required (missing or
  `null` counts as missing).
- `"_estrito": deu_bom` rejects fields the schema doesn't know — good for
  catching client typos (`"titlo"`).
- The rules (`min`, `max`, `padrao`, `opcoes`, `itens`, `campos`) are in
  [Library → Validation](/docs/en/biblioteca#validation).

`examples/api_rest.gs` validates POST and PUT this way.

## Middleware: antes() and depois()

`antes(gambiarra(pedido) ...)` ("before") runs before **every route**
(including `rota_ws`), in registration order:

- returned `nada` → moves on to the next middleware and then to the route;
- returned anything else → **that's the response**, the route doesn't even run;
- it can modify `pedido` (`bota pedido["usuario"] = ...`) and the handler sees it.

`depois(gambiarra(pedido, resposta) ...)` ("after") runs afterwards, with the
response already normalized to `{"status", "corpo", "cabecalhos"}`. Returned
`nada` → the response stands (including any in-place changes you made);
returned something else → it replaces it. Good for logging and default headers.

Middleware only runs on requests that matched a route (404/405 and static
files go straight through).

```gambiarrascript
antes(gambiarra(pedido)
    se_colar pedido.cabecalhos["Authorization"] != "Bearer segredo"
        funciona responde_json({"erro": "sem token"}, 401)
    acabou_finalmente
    bota pedido["usuario"] = "admin"
acabou_finalmente)

depois(gambiarra(pedido, resposta)
    mostra "${pedido.metodo} ${pedido.caminho} -> ${resposta.status}"
    bota resposta["cabecalhos"]["X-Servidor"] = "gambiarra"
acabou_finalmente)
```

## cors([opcoes])

Turns on CORS for the whole server: answers the preflight (`OPTIONS` with
`Access-Control-Request-Method`) with `204` and puts
`Access-Control-Allow-Origin` on responses for allowed origins.

```gambiarrascript
cors() # any origin

cors({
    "origens": ["https://meusite.com"],
    "metodos": ["GET", "POST"],
    "cabecalhos": ["Authorization", "Content-Type"],
    "credenciais": deu_bom,
    "max_idade": 600
})
```

| option | default | |
| ------ | ------- | - |
| `origens` | `["*"]` | list of exact origins (`"https://x.com"`); `"*"` allows everyone |
| `metodos` | `GET, POST, PUT, PATCH, DELETE, OPTIONS` | |
| `cabecalhos` | whatever the browser asked for | `Access-Control-Allow-Headers` |
| `credenciais` | `deu_ruim` | with `deu_bom`, sends `Allow-Credentials` and echoes the origin — **requires a list of `origens`** |
| `max_idade` | `600` | seconds to cache the preflight |

A preflight from a non-allowed origin gets `403`. Calling `cors()` again
replaces the configuration. A misspelled option is an error.

`credenciais` with any origin (`cors({"credenciais": deu_bom})`) is an error
on purpose: the browser sends the cookie along, so allowing everyone with
credentials lets **any site** make logged-in requests on behalf of your user.
List the origins that are allowed.

## serve_pasta(prefixo, pasta)

Serves static files under the prefix (`GET`/`HEAD` only; `pasta` is "folder"):

```gambiarrascript
serve_pasta("/publico", "./public") # /publico/css/site.css → ./public/css/site.css
serve_pasta("/", "./site")          # whole static site
```

- A folder → its `index.html` (no `index.html` gives `404`: no directory
  listings). `/publico` without a trailing slash redirects to `/publico/`.
- `Content-Type` by extension; `Range` and `If-Modified-Since` work.
- Security: `..` can't escape the folder, symlinks pointing outside don't
  count, and dotfiles/dot-folders (`.env`, `.git`) are never served.
- A `rota()` registered on the same path beats the folder. The folder path is
  relative to where `gs` was run.

## Forms and uploads

An `application/x-www-form-urlencoded` body (the default `<form>`) or a
`multipart/form-data` one (`<form enctype="multipart/form-data">` with
`<input type="file">`) arrives already parsed (`campos` = "fields",
`arquivos` = "files"):

```gambiarrascript
rota("POST", "/perfil", gambiarra(pedido)
    bota nome = pedido.campos.nome  # text
    bota foto = pedido.arquivos.foto  # nada if nothing was sent
    se_colar foto != nada
        bota caminho = salva_arquivo(foto, "uploads")
        mostra "${nome} sent ${foto.nome} (${foto.tamanho} bytes, ${foto.tipo}) → ${caminho}"
    acabou_finalmente
    funciona responde_json({"ok": deu_bom}, 201)
acabou_finalmente)
```

- `pedido.campos`: the text fields. A repeated field (checkbox,
  `<select multiple>`) becomes a **list**; a single one stays plain text.
- `pedido.arquivos`: each file becomes a dictionary with `nome` (name), `tipo`
  (content type), `tamanho` (size in bytes) and `conteudo_base64` (content).
  `<input type="file" multiple>` (a repeated field) becomes a list. A file
  input with no file chosen doesn't show up.
- `nome` is already **sanitized**: no directory at all (`../../etc/passwd`
  becomes `passwd`, `C:\fotos\a.png` becomes `a.png`), no control characters,
  no leading dot (no `.htaccess`) and a bounded length.
- `tipo` is what the **client** claimed (`image/png`): check the content
  before trusting it.
- `corpo` still holds the raw body; a broken form →
  `400 esse formulario do corpo ta quebrado, parca`.
- The `escuta` body limit (10 MB by default) applies to the whole upload.

### salva_arquivo(arquivo, pasta, [nome])

Writes the uploaded file **inside** `pasta` (created if missing) and returns
the final path. The name comes from the file itself (sanitized again, even if
the dictionary was built by hand) or from the 3rd argument — which must be
just a name: `/`, `\` or `..` is an error (`nada de sair da pasta, parca`).
It **never overwrites**: if `foto.png` already exists it writes `foto-1.png`,
`foto-2.png`... and returns that path.

```gambiarrascript
salva_arquivo(pedido.arquivos.doc, "uploads")  # uploads/relatorio.pdf
salva_arquivo(pedido.arquivos.doc, "uploads", "rel.pdf")  # uploads/rel.pdf
salva_arquivo(pedido.arquivos.doc, "uploads", "../x.sh")  # error
```

## Cookies: define_cookie and le_cookie

`define_cookie(resposta, nome, valor, [opcoes])` adds a `Set-Cookie` to a
response dictionary — the one from `responde_html`/`responde_json`, the
`resposta` in `depois()` or an empty `{}` — and returns that same dictionary:

```gambiarrascript
rota("GET", "/tema/:cor", gambiarra(pedido)
    bota r = responde_html("<p>theme changed</p>")
    define_cookie(r, "tema", pedido.params.cor, {"expira_em": 30 * 24 * 3600})
    funciona r
acabou_finalmente)
```

The default is the safe one: `HttpOnly` (page JavaScript can't read it) and
`SameSite=Lax` (another site can't send it along in a POST). Options:

| option       | default     | what it does                                           |
| ------------ | ----------- | ------------------------------------------------------ |
| `expira_em`  | —           | seconds (`Max-Age`); `0` or less **deletes** the cookie |
| `http_only`  | `deu_bom`   | `deu_ruim` lets JavaScript read it                     |
| `seguro`     | `deu_ruim`  | `Secure`: HTTPS only                                   |
| `mesmo_site` | `"Lax"`     | `"Strict"` or `"None"` (the latter only with `"seguro": deu_bom`) |
| `caminho`    | `"/"`       | `Path`                                                 |
| `dominio`    | —           | `Domain`                                               |
| `segredo`    | —           | **signs** the value with HMAC-SHA256 (32+ characters)  |

The value is text without quotes, `;`, `\` or accents (run it through
`base64_codifica`, or keep real data in the session).

`le_cookie(pedido, nome, [segredo])` reads the cookie from the request
(`nada` if absent). With `segredo` it only returns the value if the
`define_cookie` signature matches: a tampered or unsigned cookie → `nada`,
no error.

```gambiarrascript
bota SEGREDO = env("SEGREDO")
# on login:  define_cookie(r, "usuario", texto(id), {"segredo": SEGREDO})
# later:     bota id = le_cookie(pedido, "usuario", SEGREDO)  -- nada = forged
```

## Sessions: usa_sessao(opcoes)

Sessions **without a database**: `pedido.sessao` becomes a dictionary that
comes back on the next request from the same browser. It lives entirely in a
cookie signed with HMAC-SHA256 — the user may read it but can't change it.

```gambiarrascript
usa_sessao({"segredo": env("SEGREDO")})  # gera_chave() once and keep it in .env

rota("GET", "/", gambiarra(pedido)
    bota pedido.sessao["visitas"] = (pedido.sessao.visitas ?? 0) + 1
    funciona "visit number ${pedido.sessao.visitas}"
acabou_finalmente)

rota("POST", "/sair", gambiarra(pedido)
    bota pedido["sessao"] = {}  # empty session = deletes the cookie
    funciona "bye!"
acabou_finalmente)
```

- Changed `pedido.sessao` (in the route, in `antes` or in `depois`) → the
  server sends the new cookie. Didn't change it → nothing is sent (and it
  renews itself once past half of its lifetime).
- A **tampered** cookie, one from another secret, broken or expired → an
  **empty** session, no error.
- Only what turns into JSON fits (text, number, boolean, nada, list,
  dictionary), up to about 4 KB (the browser limit). Going over, or storing a
  function → 500 with the reason on stderr. For big things, keep just an id in
  the session.
- On WebSocket `pedido.sessao` is read-only (the handshake is already done).

| option       | default       | what it does                                       |
| ------------ | ------------- | -------------------------------------------------- |
| `segredo`    | required      | 32+ characters (`gera_chave()` works)              |
| `nome`       | `"gs_sessao"` | cookie name                                        |
| `encripta`   | `deu_ruim`    | `deu_bom` encrypts with AES-256-GCM: the user can't even read it |
| `expira_em`  | 7 days        | seconds; an older cookie is not accepted           |
| `seguro`, `mesmo_site`, `caminho`, `dominio`, `http_only` | as in `define_cookie` | |

## Rate limiting: limita(opcoes)

`limita({"por_minuto": 60})` ("60 per minute") holds each client in a
**token bucket**: the bucket starts full (`rajada`, the burst, default =
`por_minuto`), each request spends a token and tokens trickle back. No token
→ `429` with `Retry-After` (in seconds) and the route doesn't even run.

```gambiarrascript
limita({"por_minuto": 120})  # global, per ip

# login: 5 per minute per email (a request without email skips this limit)
gambiarra chave_login(pedido)
    funciona pedido.campos.email
acabou_finalmente
limita({"por_minuto": 5, "prefixo": "/login", "chave": chave_login})
```

| option       | default       | what it does                                       |
| ------------ | ------------- | -------------------------------------------------- |
| `por_minuto` | required      | tokens refilled per minute                         |
| `rajada`     | `por_minuto`  | bucket size (how many at once)                     |
| `chave`      | `"ip"`        | or a `gambiarra(pedido)` returning the key; `nada` = this request skips the limit |
| `prefixo`    | everything    | only paths under it (`"/api"` covers `/api` and `/api/x`) |
| `max_chaves` | 10000         | how many clients it remembers; beyond that it forgets the oldest |

- You can call it several times: every limit applies, in order.
- It runs **before** `antes()` (and the 429 goes through `depois()` like any
  response). It also applies to the WebSocket handshake.
- Behind a proxy the ip is the proxy's: use `"chave"` with the
  `X-Forwarded-For` that **your** proxy sets.
- Memory is bounded (`max_chaves`); a forgotten client comes back with a full
  bucket.

## Compression: comprime([opcoes])

`comprime()` sends responses **gzipped** when it pays off:

- the client accepts it (`Accept-Encoding: gzip`);
- the body has at least `minimo` bytes (default 1024);
- the type is text: `text/*`, JSON, JavaScript, XML, SVG, WASM. Images, zips
  and videos are already compressed and go as is;
- the response has no `Content-Encoding` yet (never compresses twice).

Every response that *could* be compressed gets `Vary: Accept-Encoding` (so
caches don't hand gzip to someone who didn't ask). It applies to routes and
to `serve_pasta` (except requests with `Range`). Options: `minimo` (bytes) and
`nivel` (level: 1 = fast ... 9 = smallest).

```gambiarrascript
comprime({"minimo": 512})
```

## escuta(porta, [opcoes])

Starts the server and **blocks**. Takes a number (`8080`) or text with the
address (`":8080"`, `"127.0.0.1:3000"`, `"0"`/`"127.0.0.1:0"` = any free
port). Prints the real address to **stderr**:

```
servidor de pe em http://localhost:8080 (ctrl+c pra parar)
```

- **ctrl+c / SIGTERM** shuts down gracefully: stops accepting connections,
  waits up to 5s for in-flight requests, notifies WebSockets ("going away")
  and `escuta` **returns** — the code after it runs (close the database, save
  state). A second ctrl+c kills it on the spot.
- Timeouts: 10s for the request headers to arrive, 60s to read the body, 120s
  for an idle connection (keep-alive).
- Maximum body: **10 MB** by default (json, text, forms, uploads). Over it →
  `413 corpo grande demais, parca (o limite e N bytes)` without calling the
  route. Change it with `escuta(8080, {"max_corpo": 50 * 1024 * 1024})`.

Each request runs **in parallel** (one goroutine per request). So be careful
when touching a list/dictionary shared between handlers (see
[Concurrency](/docs/en/concorrencia#shared-state)): each operation on a
collection is atomic, but a compound one (`bota d["n"] = d["n"] + 1`) needs
`com_trava(trava, gambiarra() ... acabou_finalmente)` (`trava` = "lock").

## HTTPS: `escuta(porta, {"tls": ...})`

```gambiarrascript
rota("GET", "/", gambiarra() funciona "salve, seguro" acabou_finalmente)
escuta(8443, {"tls": {"cert": "cert.pem", "chave": "chave.pem"}})
```

```
servidor de pe em https://localhost:8443 (ctrl+c pra parar)
```

- `cert` and `chave` ("key") are the **PEM** files for the certificate (with
  the chain, if there's an intermediate — Let's Encrypt's `fullchain.pem`) and
  the private key. Text starting with `-----BEGIN` is treated as the PEM
  itself (see `gera_certificado` below).
- The certificate is read **before** the port opens: a file that doesn't
  exist or isn't valid PEM (or a key from another certificate) raises an
  `"io"` error right away, with the path in the message — no server that's up
  but kills every handshake.
- TLS **1.2 minimum**; cipher suites and curves stay on Go's defaults (only
  the safe ones). HTTP/2 comes as a freebie for whoever asks for it.
- **`rota_ws` becomes `wss://`** on its own: same port, same certificate.
- Everything else (routes, middleware, graceful shutdown, timeouts) is the
  same. A client speaking `http://` on the https port, or one that doesn't
  trust the certificate, doesn't pollute stderr: the error shows up on its side.

<Callout title="In production">
  Often TLS terminates **before** your server: a reverse proxy (nginx, Caddy,
  Traefik) or the cloud load balancer holds the certificate (and renews it on
  its own) and forwards plain HTTP to `escuta(8080)` on the internal network.
  In that case you don't need `{"tls": ...}` — and the client IP comes in the
  `X-Forwarded-For` header. The `tls` here is for when `gs` is exposed
  directly, or for testing `https://`/`wss://` at home.
</Callout>

### gera_certificado([hosts]) — development only

```gambiarrascript
bota par = gera_certificado()      # {"cert": "-----BEGIN CERTIFICATE-----...", "chave": "-----BEGIN PRIVATE KEY-----..."}
escreve_arquivo("cert.pem", par.cert) # so curl --cacert / another client can trust it
escuta(8443, {"tls": par})         # the PEM itself works in place of the path
```

Generates a **self-signed** certificate (ECDSA P-256, valid for 1 year) and
returns `{"cert", "chave"}` in PEM. Default hosts: `localhost`, `127.0.0.1`
and `::1`; pass others with `gera_certificado(["meu.dev", "192.168.0.10"])`
(an IP becomes an IP, everything else becomes a name). It is its own CA, so a
client trusts it by passing the `cert` as `ca`: `busca(url, {"ca": par.cert})`
or `curl --cacert cert.pem`.

<Callout title="Don't use it in production">
  No browser trusts this certificate (it will show a warning). In production
  use a real certificate (Let's Encrypt, your provider's) or let the reverse
  proxy handle TLS. The key comes out as plain text: don't commit `chave.pem`.
</Callout>

## WebSocket: rota_ws(caminho, handler, [opcoes])

With `escuta(porta, {"tls": ...})` the same endpoint serves `wss://`.

```gambiarrascript
bota conexoes = []

rota_ws("/chat", gambiarra(ws, pedido)
    adiciona(conexoes, ws)
    enquanto deu_bom
        bota msg = recebe(ws) # blocks; nada = the client left
        se_colar msg == nada
            vaza
        acabou_finalmente
        pra_cada c em conexoes
            envia(c, {"de": pedido.query.nome, "texto": msg})
        acabou_finalmente
    acabou_finalmente
    remove(conexoes, ws)
acabou_finalmente)

escuta(8080)
```

- The handler runs **once per connection**, in that connection's goroutine,
  and receives the `ws` connection and the same `pedido` as HTTP routes
  (`params`, `query`, `cabecalhos`, `cookies`...). The path accepts
  `:param`/`*curinga`.
- `antes()` runs before the handshake: returning a response (e.g. `401`)
  rejects the connection.
- `recebe(ws)` ("receive") blocks until the next message and returns **text**.
  It returns `nada` when the client closed, dropped, or the server is shutting
  down — that's the signal to leave the loop.
- `envia(ws, x)` ("send"): text goes as is; **lists/dictionaries go as JSON**
  (`pra_json`); numbers/booleans become text. You can call it on the same
  connection from several goroutines at once (sending is serialized per
  connection). Sending to a connection that **already dropped doesn't blow
  up** (the message is lost) — the broadcast doesn't break because one client
  left. Sending after you yourself called `fecha(ws)` is an error. A client
  that doesn't read for 10s gets dropped.
- `fecha(ws)` ("close") closes it (idempotent). When the handler finishes, the
  connection closes on its own; if it blows up with an error, it closes with
  code 1011 and the error goes to stderr.
- Keepalive: the server sends a ping every 30s while someone is in `recebe`;
  no pong within 15s and the connection is dropped and `recebe` returns `nada`.
- Origin: by default only browsers from the **same origin** are accepted. The
  handshake carries cookies from any site, so allowing an origin on the
  websocket means handing it the user's login — that's why an open `cors()`
  does **not** apply here. To allow, list them on the route itself:
  `rota_ws("/chat", h, {"origens": ["https://app.com"]})`; `["*"]` allows any
  (only do that if the socket doesn't depend on login). A `cors()` with a list
  of origins also counts. Clients outside the browser (no `Origin`) always get in.
- Messages up to 1 MiB.

A plain `GET` (no upgrade) on a `rota_ws` gets `426`.

### conecta_ws(url, [opcoes]) — client

```gambiarrascript
bota ws = conecta_ws("ws://localhost:8080/chat?nome=ze", {"cabecalhos": {"Authorization": "Bearer x"}, "timeout": 5})
envia(ws, "salve")
mostra recebe(ws)
fecha(ws)
```

Same connection as the server's: `envia`/`recebe`/`fecha` work the same way.
`timeout` (seconds, default 30) only applies to connecting. `wss://` validates
the certificate against the system CAs; to talk to a dev server with its own
certificate, use `{"ca": "cert.pem"}` (a path or the PEM itself — with it,
only that CA counts) or, as a last resort, `{"inseguro": deu_bom}` ("insecure")
— the same options as
[`busca`](/docs/en/http#https-with-your-own-certificate-ca-and-inseguro).
Failed → network error
(`conecta_ws(): nao consegui conectar em "ws://..." (o servidor respondeu 401): ...`).
WebSocket doesn't run in the playground (browser).

## Deploying with Docker

The [official image](/docs/en/instalacao#3-official-docker-image) already has
`gs` as its `ENTRYPOINT` and `/app` as the working directory. To package an
API, a 4-line `Dockerfile` does it:

```dockerfile
FROM ghcr.io/erikomis/gambiarrascript:latest
COPY --chown=nonroot:nonroot . /app
EXPOSE 8080
CMD ["roda", "api.gs"]
```

```gambiarrascript
# api.gs
rota("GET", "/saude", gambiarra(req) funciona "ok" acabou_finalmente)
escuta(env("PORTA", "8080"))
```

```bash
docker build -t my-api .
docker run --rm -p 8080:8080 my-api
```

- Listen on every interface (`escuta(8080)` or `":8080"`); `"127.0.0.1:8080"`
  isn't reachable from outside the container.
- `docker stop` sends SIGTERM: `escuta` shuts down gracefully (see above) and
  schedules (`a_cada`, `agenda`) stop with it.
- `--chown` lets the `nonroot` user write to `/app` (sqlite database,
  `roda --cache`, uploads). For data that must outlive the container, use a
  volume: `docker run -v data:/app/data ...`.
- Pin the version (`:0.8.0`) in production; `:latest` moves with every stable
  release. Add a `.dockerignore` so `.git` and friends aren't copied.
- A worker with no server (just `agenda`/`a_cada`) works the same way: `gs
  roda` stays up while there are schedules.
