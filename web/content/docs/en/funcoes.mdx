---
title: Gambiarra (functions)
description: How to declare and call functions in GambiarraScript - default parameters, varargs, lambdas and closures.
---

A function is a Gambiarra (a duct-tape hack). `gambiarra` declares it,
`funciona` ("works") returns. The obvious way to close it is
`acabou_finalmente` ("finally over").

## Declaring and calling

```gambiarrascript
gambiarra saudacao(nome)
    mostra "salve, " + nome
acabou_finalmente

saudacao("Jurandir")        # salve, Jurandir
```

## Return

```gambiarrascript
gambiarra dobra(n)
    funciona n * 2
acabou_finalmente

mostra dobra(21)        # 42
```

`funciona` always takes an expression — to return "nothing", write
`funciona nada`. A gambiarra that ends without `funciona` returns `nada`.

## Parameters with default values

`nome = valor` makes the parameter optional. The default can use the earlier
parameters:

```gambiarrascript
gambiarra cumprimenta(nome, saudacao = "salve")
    funciona saudacao + ", " + nome
acabou_finalmente

mostra cumprimenta("Jurandir")            # salve, Jurandir
mostra cumprimenta("Jurandir", "fala")    # fala, Jurandir

gambiarra retangulo(largura, altura = largura)
    funciona largura * altura
acabou_finalmente
mostra retangulo(3)                   # 9 (square)
```

## Varargs

`...resto` in the last parameter gathers the leftover arguments into a list:

```gambiarrascript
gambiarra soma_tudo(primeiro, ...resto)
    bota total = primeiro
    pra_cada x em resto
        total += x
    acabou_finalmente
    funciona total
acabou_finalmente

mostra soma_tudo(1)             # 1
mostra soma_tudo(1, 2, 3, 4)    # 10
```

## Spreading a list into a call (`f(...lista)`)

The reverse of varargs: `...lista` **inside the call** spreads the list's items
as separate arguments. You can mix it with plain arguments, use more than one
`...` in the same call, and it works for builtins too:

```gambiarrascript
gambiarra soma3(a, b, c)
    funciona a + b + c
acabou_finalmente

bota xs = [1, 2, 3]
mostra soma3(...xs)                  # 6
mostra soma3(10, ...[20, 30])        # 60
mostra max(...xs)                    # 3
mostra max(0, ...xs, 9, ...[4, 5])   # 9

bota args = ["%s tem %d anos", "Jurandir", 25]
mostra formata(...args)              # Jurandir tem 25 anos
```

It works on anything callable — a named gambiarra, a lambda, a dot call
(`modulo.f(...xs)`), `bora` — and plays nicely with varargs and default
parameters (the arity is checked **after** spreading):

```gambiarrascript
gambiarra soma_tudo(primeiro, ...resto)
    bota total = primeiro
    pra_cada x em resto
        total += x
    acabou_finalmente
    funciona total
acabou_finalmente

gambiarra cumprimenta(nome, saudacao = "salve")
    funciona saudacao + ", " + nome
acabou_finalmente

bota dobra = gambiarra(x) funciona x * 2 acabou_finalmente
bota ops = {"soma": soma_tudo}

mostra soma_tudo(...[1, 2], ...[3, 4])        # 10
mostra cumprimenta(...["Jurandir"])           # salve, Jurandir
mostra cumprimenta(...["Jurandir", "fala"])   # fala, Jurandir
mostra dobra(...[21])                         # 42
mostra ops.soma(...[5, 5])                    # 10
mostra espera(bora soma_tudo(...[1, 2, 3]))   # 6
```

Only a **list** can be spread. Anything else is a runtime error (which
`arruma` ("fix it") catches):

```gambiarrascript
arruma
    mostra max(...42)
quebrou erro
    mostra erro_msg(erro)    # deu ruim na linha 2: so da pra espalhar lista, veio numero
acabou_finalmente
```

And `...` only exists in those two places — in the last parameter of the
declaration (`gambiarra f(...resto)`) and inside the call's parentheses.
Anywhere else (`[...xs]`, `bota y = ...xs`) it's a syntax error before
anything runs.

## Arity

Apart from the optional ones and `...resto`, the number of arguments has to
match. Too few or too many is a runtime error:

```gambiarrascript
gambiarra soma(a, b)
    funciona a + b
acabou_finalmente

mostra soma(2, 3)       # 5
mostra soma(2)          # erro: essa gambiarra quer 2 parametro(s), voce mandou 1
```

## Lambdas (anonymous gambiarra)

Without a name, `gambiarra(params) ... acabou_finalmente` is an
**expression**: you can store it in a variable, a list, a dict, or pass it
straight to another builtin. It fits on a single line:

```gambiarrascript
bota dobra = gambiarra(x) funciona x * 2 acabou_finalmente
mostra dobra(4)                                  # 8

bota ops = [gambiarra(x) funciona x + 1 acabou_finalmente,
            gambiarra(x) funciona x * 2 acabou_finalmente]
mostra ops[1](10)                                # 20

mostra mapeia([1, 2, 3], gambiarra(n) funciona n * n acabou_finalmente)   # [1, 4, 9]
```

Functions are first-class: a named gambiarra is a value too
(`mapeia(xs, dobra)`, `rota("GET", "/", handler)`).

## Closures

A gambiarra created inside another one sees the outer variables, even after
the outer one has already finished:

```gambiarrascript
gambiarra multiplicador(fator)
    funciona gambiarra(x) funciona x * fator acabou_finalmente
acabou_finalmente

bota triplica = multiplicador(3)
mostra triplica(5)          # 15
```

The closure sees the outer **variable**, not a copy of its value: if it changes
after the closure was created, the closure sees the new value (and closures
created in a loop see the last value of the loop variable — see
[Gotchas](/docs/en/pegadinhas#a-closure-sees-the-variable-not-a-copy)). That
also lets a nested gambiarra call itself or a sibling declared after it.

<Callout type="warn" title="Assigning inside the function creates a local variable">
  Reading an outer variable works; **assigning** (`bota x = ...` or
  `x += ...`) inside a gambiarra creates a **local** variable — in the whole
  function, just like Python without `nonlocal`. The outer one doesn't change
  (reading before assigning still sees the outer one; see
  [Gotchas](/docs/en/pegadinhas)). For shared state, keep it in a dict or a
  list (they're passed by reference) and change the contents:
</Callout>

```gambiarrascript
gambiarra contador()
    bota estado = {"n": 0}
    funciona gambiarra()
        estado.n += 1          # changes the dict, not the variable
        funciona estado.n
    acabou_finalmente
acabou_finalmente

bota proximo = contador()
proximo()
proximo()
mostra proximo()            # 3
```

## Recursion

Plain recursion works up to **1024** stacked calls; past that, you get a clean
error ("recursao funda demais"). If the recursive call is the very last thing
(`funciona f(...)` calling the same gambiarra), it becomes a **tail call** and
doesn't stack up — it can go as deep as you like:

```gambiarrascript
gambiarra fatorial(n, acc = 1)
    se_colar n <= 1
        funciona acc
    acabou_finalmente
    funciona fatorial(n - 1, acc * n)    # tail call
acabou_finalmente

mostra fatorial(20)         # 2432902008176640000
```

## Generators (`rende`)

A gambiarra with `rende` inside becomes a **generator**: calling it **does not
run the body** — it returns a value of type `gerador`. Each time someone asks
for a value, the body runs up to the next `rende`, hands the value over and
**pauses right there** (locals, loops, everything stays as it was) until the
next request.

```gambiarrascript
gambiarra conta(n)
    pra_cada i de 1 ate n
        rende i * 10
    acabou_finalmente
acabou_finalmente

bota g = conta(3)
mostra tipo(g)              # gerador
mostra g                    # <gerador conta>
pra_cada x em g
    mostra x                # 10, 20, 30
acabou_finalmente
```

Since the body only runs on demand, an **infinite** generator is fine — `vaza`
stops asking:

```gambiarrascript
gambiarra naturais()
    bota n = 0
    enquanto deu_bom
        rende n
        n += 1
    acabou_finalmente
acabou_finalmente

pra_cada i, x em naturais()     # two names: position and value
    se_colar x > 2
        vaza
    acabou_finalmente
    mostra "${i}: ${x}"
acabou_finalmente
mostra pega(naturais(), 5)      # [0, 1, 2, 3, 4]
```

- **Asking by hand**: `proximo(g)` returns the next value, or `nada` once the
  generator is done. Since a generator may yield `nada` on purpose, use
  `proximo(g, padrao)` (returns the default at the end) or `acabou(g)` to be
  sure. `acabou(g)` may have to run the body up to the next `rende` to find
  out (a `mostra` in there shows up at that moment); the value is kept for the
  next request.
- **A generator only moves forward**: what came out does not come back. A
  `vaza` in the middle of a `pra_cada` over a generator **kept in a variable**
  leaves it paused where it was — the next `pra_cada` (or `proximo`) continues
  from there (a generator created in the `pra_cada` itself is closed on the way
  out: see [Closing](#closing-fecha)). A finished generator stays finished; to
  start over, call the gambiarra again (each call is an independent generator).
- **`lista(g)`** pulls everything into a list; **`pega(g, n)`** pulls up to `n`
  values. `mapeia`, `filtra` and `reduz` take a generator directly, but
  **consume it entirely** first (and return a list) — with an infinite
  generator they never return: use `pega` first, or a generator that filters
  another one.
- **`funciona` ends** the generator (the value is thrown away; `gs check` warns
  — prefer `funciona nada`). Falling off the end of the body also ends it.
- An **error** inside the generator blows up where the value was requested (the
  `pra_cada`, the `proximo`...), with the line from inside the generator, and
  you can catch it with `arruma` around the consumer. After an error the
  generator is done.
- **Parameters** are bound at the call (defaults included): changing the
  variable you passed afterwards does not change the generator.
- Works for named gambiarras, lambdas and methods. A `rende` inside an inner
  lambda belongs to the lambda (only it becomes a generator). `rende` outside a
  gambiarra is a syntax error.
- A generator can be used from several goroutines (`bora`): one request at a
  time, each value comes out once. A generator that asks for its own next value
  while running is an error (it would never move). The body runs in the flow of
  whoever asked: taking, with `com_trava`, a lock the consumer is holding is
  the usual re-entrance (an error, not a hang).

### Closing (`fecha`)

`fecha(g)` ends a paused generator **running the body's pending `finalmente`
blocks** (like Python's `close()`). `pra_cada` does it on its own for a
generator born in its header:

```gambiarrascript
gambiarra naturais()
    bota n = 0
    arruma
        enquanto deu_bom
            rende n
            n += 1
        acabou_finalmente
    finalmente
        mostra "limpou em " + texto(n)
    acabou_finalmente
acabou_finalmente

bota g = naturais()
mostra proximo(g)        # 0
mostra proximo(g)        # 1
fecha(g)                 # limpou em 1
mostra proximo(g)        # nada (closed = finished)

pra_cada x em naturais() # the loop owns the generator
    se_colar x == 2
        vaza             # limpou em 2
    acabou_finalmente
acabou_finalmente
```

- `fecha` resumes the body with a **close signal** in place of the `rende`: it
  unwinds the body and only `finalmente` sees it go by — `quebrou` **does not
  catch it**. After that the generator is finished. Closing again does
  nothing; a generator that never started just ends (nothing was pending).
- If the body hits a `rende` while closing (a `rende` inside the `finalmente`,
  say), `fecha` throws:
  `o gerador naturais ignorou o fecha (deu rende enquanto fechava)`. An error raised in the `finalmente` goes up to whoever closed it
  (catch it with `arruma` around the `fecha`).
- **Automatic close**: `pra_cada` **owns** a generator created in its own
  header (`pra_cada x em naturais()`, or a treta's `itera()` returning a new
  generator). Leaving before the end — `vaza`, `funciona` or an error going up
  — closes the generator right there, like a `finalmente` around the loop (an
  error while closing replaces whatever was leaving). A generator that existed
  before the loop (variable, parameter, field) is **not** closed: you can
  resume it later. `sai()` closes nothing (the program is ending).
- In a pipeline such as `pares(naturais())`, closing `pares` only closes what
  it created itself in a `pra_cada`: `naturais()` came from outside, so it
  stays paused until it is garbage, without running its `finalmente`. To close
  in a chain, create the inner generator in the header of the outer one's
  `pra_cada`.
- A generator that closes itself while running is an error (it would never
  move).

Generator combining generator (lazy pipeline):

```gambiarrascript
gambiarra pares(origem)
    pra_cada x em origem
        se_colar x % 2 == 0
            rende x
        acabou_finalmente
    acabou_finalmente
acabou_finalmente

mostra pega(pares(naturais()), 4)   # [0, 2, 4, 6]
```

To make a treta walkable with `pra_cada`, give it an `itera()` (which can be a
generator) — see [Walking a treta](/docs/en/poo#walking-a-treta).

## Documenting

`#` comments right above a `gambiarra` (or a top-level `crava`) become
documentation in `gs doc arquivo.gs` (it generates markdown with the signature
and the comment). See [Command line](/docs/en/cli#gs-doc).

```gambiarrascript
# devolve o dobro de n
gambiarra dobra(n)
    funciona n * 2
acabou_finalmente
```

<Callout type="warn" title="Scope of pra_cada">
  The `pra_cada` variable and the one from the `quebrou` ("it broke") clause
  **leak** into the scope of the function that contains the block — same
  style as Python. See [Gotchas](/docs/en/pegadinhas).
</Callout>
