GambiarraScript vem com tres ferramentas: uma extensao pro VSCode, um servidor
LSP (que qualquer editor moderno consegue usar) e um formatter de linha de
comando.

## Extensao VSCode (recomendado)

A extensao empacota tudo: highlight, snippets, comando de rodar, LSP.

### Instalar

Precisa do `gs` no `PATH` (veja [Instalacao](/docs/instalacao)).

O jeito mais facil: toda
[release no GitHub](https://github.com/erikomis/gambiarrascript/releases) traz
o `.vsix` da extensao pronto (`gambiarrascript-<versao>.vsix`), junto dos
binarios. Baixa ele e, dentro do VSCode: `Extensions` → menu `...` →
`Install from VSIX...` → escolhe o arquivo. Ou pelo terminal:

```bash
code --install-extension gambiarrascript-<versao>.vsix
```

#### Compilando do repo

Prefere gerar na mao? Pra compilar a extensao:

```bash
./scripts/build-extension
# o repo tambem traz um pacote pronto: editors/vscode/gambiarrascript-0.1.0.vsix
```

Depois instala no VSCode:

```bash
code --install-extension editors/vscode/gambiarrascript-0.1.0.vsix
```

Ou, dentro do VSCode: `Extensions` → `...` menu → `Install from VSIX...` →
aponta o `gambiarrascript-0.1.0.vsix`.

### O que ela tem

- **Syntax highlight** baseado em TextMate (`syntaxes/gambiarrascript.tmLanguage.json`)
  — o mesmo grammar que colore os exemplos desta documentacao.
- **Snippets** (`snippets/gambiarrascript.json`) pros blocos e builtins mais
  usados: `gambiarra`, `se_colar`, `pra_cada`, `pra_cada_em`, `enquanto`,
  `arruma`, `importa`, `busca`, `rota`, `bora`, `cano`...
- **Rodar arquivo**: tecla `F5` ou `cmd/Ctrl+R`, command palette
  `GambiarraScript: Rodar arquivo`.
- **Abrir REPL**: command `GambiarraScript: Abrir REPL`.
- **LSP integrado**: diagnosticos, autocomplete, hover, ir pra definicao
  (`F12`), achar referencias (`Shift+F12`), renomear (`F2`), outline do
  arquivo, ajuda de assinatura enquanto digita a chamada e formatar documento
  (`Shift+Alt+F`) — detalhes na secao [LSP](#lsp-gs-lsp) abaixo.
- Icone `.gs` customizado.

### Config

- `gambiarrascript.caminhoDoGs` (default `"gs"`): caminho do binario `gs`.
  Sete pra um absoluto se o `gs` nao estiver no `PATH`.

## LSP (`gs lsp`)

O servidor LSP usa stdin/stdout em JSON-RPC. Suporta:

| feature | o que faz |
| --- | --- |
| Diagnosticos | em `didOpen`/`didChange`: erros de sintaxe com linha/coluna + avisos do lint |
| Autocomplete | palavras-chave, builtins, identificadores |
| Hover | descricao curta de palavras-chave e builtins |
| Ir pra definicao | pula pra onde o nome foi declarado (`bota`, `crava`, `gambiarra`, parametro...), inclusive em **outro arquivo** quando o nome veio de um `importa`; com o cursor no caminho do `importa "x.gs"`, abre o arquivo |
| Referencias | lista todo uso do nome; nome de topo e procurado tambem nos arquivos que importam ele (`importa "x.gs"` e `importa "x.gs" como m` → `m.nome`) |
| Renomear | troca o nome em todas as referencias, entre arquivos tambem. Recusa palavra-chave, builtin, nome invalido e nome que ja existe no escopo (ou que mudaria o significado de outra referencia) |
| Outline (document symbols) | gambiarras (com as aninhadas dentro), variaveis e constantes de topo e os `importa ... como` |
| Ajuda de assinatura | ao digitar `(` ou `,` numa chamada, mostra os parametros (com padrao e `...resto`) e destaca o atual — pra gambiarra sua (o comentario `#` de cima vira a doc) e pra builtin |
| Formatar documento | o mesmo formatter do [`gs formata`](#formatter-gs-formata); arquivo com erro de sintaxe nao e mexido |

Os avisos do lint sao os mesmos do `gs check`: nome que nao existe (nao e
builtin, palavra-chave, variavel, parametro nem `quebrou`), variavel `bota`
declarada e nunca usada (fora do topo do arquivo) e codigo morto depois de
`funciona`/`vaza`/`continua`. Reatribuir um nome cravado (`crava`) aparece como
**erro**, igual no `gs roda`.

### Configurando o LSP em outros editores

#### Neovim (com `nvim-lspconfig`)

```lua
local configs = require 'lspconfig.configs'
if not configs.gambiarrascript then
  configs.gambiarrascript = {
    default_config = {
      cmd = { 'gs', 'lsp' },
      filetypes = { 'gambiarrascript' },
      root_dir = function(fname) return vim.fn.getcwd() end,
      settings = {},
    },
  }
end
require('lspconfig').gambiarrascript.setup {}
```

Adiciona a extensao `.gs` em `filetype`:

```vim
autocmd BufRead,BufNewFile *.gs set filetype=gambiarrascript
```

#### Helix

Em `~/.config/helix/languages.toml`:

```toml
[[language]]
name = "gambiarrascript"
scope = "source.gambiarrascript"
file-types = ["gs"]
roots = []
comment-token = "#"

[language-server.gambiarrascript]
command = "gs"
args = ["lsp"]
```

#### Zed

```json
{
  "languages": {
    "GambiarraScript": {
      "language_servers": ["gambiarrascript"],
      "extensions": ["gs"]
    }
  },
  "lsp": {
    "gambiarrascript": {
      "binary": { "path": "gs", "args": ["lsp"] }
    }
  }
}
```

## Formatter (`gs formata`)

```bash
gs formata sujo.gs > lindo.gs     # imprime formatado
gs formata -w sujo.gs             # sobrescreve o arquivo (so se mudou)
gs formata -w .                   # todos os .gs da pasta, recursivo
```

O formatter re-emite o AST. Regras:

- Indent: **4 espacos** por nivel.
- Blocos: abre em linha separada, fecha com `acabou_finalmente` no nivel pai.
- `else if` vira `se_nao_colar se_colar ...`.
- Infix recebe parenteses so quando a precedencia exige.
- Listas e dicionarios ficam inline, a nao ser que voce quebre a linha logo
  depois do `[`/`{` — ai sai um item por linha. Lambda escrita em varias
  linhas vira bloco indentado; lambda de uma linha fica inline.
- Atribuicao composta (`x += 1`) e interpolacao (`"${x}"`) sao preservadas.
- Texto e re-citado com aspas duplas — escapes normalizados (`\"`, `\\`, `\n`)
  e string de crase vira string de aspas equivalente.
- **Comentarios ficam**: `#` sozinho na linha e reindentado pro nivel do
  bloco; `#` depois do codigo fica na mesma linha, com 2 espacos antes;
  `/* */` sai igualzinho. `#` dentro de texto nao e comentario e nao e tocado.
- Linhas em branco ficam (varias seguidas viram uma; nenhuma no comeco ou no
  fim de bloco).
- Comentario no meio de uma expressao quebrada em varias linhas (chamada,
  condicao) vai pra linha de cima, porque a expressao volta pra uma linha so.

<Callout title="Trava de seguranca">
  Antes de gravar, o `gs formata -w` (e o "formatar documento" do editor)
  confere que o resultado tem o mesmo codigo e exatamente os mesmos
  comentarios. Se nao tiver, nao grava: avisa `NAO formatado` e o arquivo
  fica como estava.
</Callout>

### Indentacao

Indentacao visual e livre na linguagem (nao e significativa como em Python);
o que conta e o par `se_colar`/`acabou_finalmente`. O formatter impoe 4
espacos pra ficar consistente.

## Highlight fora do editor

O grammar TextMate da extensao (`editors/vscode/syntaxes/gambiarrascript.tmLanguage.json`)
funciona em qualquer ferramenta que fale TextMate — e o que esta documentacao
usa (via shiki) nos blocos de codigo marcados como `gambiarrascript` (ou
`gs`). O
[playground](/playground) tem o highlight proprio dele, no editor do navegador.
